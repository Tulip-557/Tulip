# 用户授权登录：能不能「用你的账号读社媒」

> 这一页回答两个常被问的问题：
> ① 「我授权登录一下，你是不是就能读到小红书/抖音了？」
> ② 「GitHub 上有现成的工具，装上是不是就行了？」
>
> 答案都在下面，但**先把结论放最前面**，因为它决定了要不要往下做。

---

## 一、先看这条结论（别读漏）

**登录只提升「覆盖度」，不提升「证据等级」。**

| | 匿名路径（现在默认） | 登录路径（AUTH 档） |
|---|---|---|
| 能拿到的内容 | 官方发布、OTA 攻略、微博/B站公开页、公众号原文 | 上面全部 **+** 小红书/抖音笔记正文 |
| 证据等级上限 | `[B]`（官方发布互证） | **仍然 `[B]`**；UGC 部分仍是 `[C·单源]` |
| 账号风险 | 无 | **有**（限流 / 验证 / 极端情况封号） |
| 是否违反平台条款 | 否 | **是**（平台用户协议普遍禁止自动化采集） |
| 现金成本 | 0 | 0（自建）～ 按次付费（第三方 API） |

为什么等级不变？因为等级定义与「读得多少」无关：

- `[A]` = **工具实证**（官方接口返回、政府门户）。UGC 无论怎么读都不是工具实证。
- `[B]` = **两个独立来源互证**。小红书笔记不因你登录了就变成两个来源。
- `[C·单源]` = 单一来源线索。**这就是 UGC 的天花板。**

所以登录换来的是「多几条线索」，代价是「你的账号有风险」。**值不值，取决于官方路径拿不到的那部分内容值不值这个风险**——而不是取决于技术能不能做到。

> 顺带一提：社媒情报本来就不许提供「票价 / 营业时间 / 车次余票 / 距离车程」。
> 登录能多拿的，主要是**体验、机位、人流、玩法**这类定性内容。

## 二、三种强度（强度递增，风险也递增）

| 强度 | 渠道 id | 怎么做 | 账号风险 | 本项目立场 |
|---|---|---|---|---|
| ① 人工辅助 | `user_provided` | 你自己刷到 → 贴链接/截图 → 只读读取 | 无 | **默认走这条** |
| ② 半自动读取 | `logged_in_cdp` | 独立 profile 扫码一次 → 之后 headless 复用该 profile 读**一页** | 低（就跟你自己看一样） | **可用，需你点头** |
| ③ 批量采集 | `local_crawler` | 装 MediaCrawler 类工具，扫码 + 并发翻页 + 采评论 | **中高** | **不默认启用**，要用须显式拍板 |

第 ① 条为什么也算「用户授权登录」？因为**真实用户能打开采集端打不开的页面**——你手机上刷到的那条笔记，就是我能拿到的最干净的一手 UGC。它不需要任何自动化，风险为零。

第 ② 条是本轮落地的那条，工具已经写好（见第四节）。

第 ③ 条技术上最强，但它走的是「签名对抗」路线（逆向平台参数），**与本项目「不绕风控」的铁律正面对冲**，所以只登记、不启用。

## 三、实测结论（2026-09-27，本机 Edge 154.0.4258.37）

### 3.1 为什么不能直接用你正在用的浏览器

这是最先要搞清的一件事。实测两条：

| 试法 | 结果 |
|---|---|
| 直接复制主 profile 的 `Cookies` 文件 | ❌ `err=32` 共享冲突——Edge 对 Cookies 持**独占锁** |
| 用主 `--user-data-dir` 再起一个实例加调试端口 | ❌ 起不来（Edge 正在运行，同 profile 互斥） |

**结论：复用「你日常那个浏览器」的登录态，技术上做不到。**
能做的是：**开一个独立 profile 登录一次，之后一直复用它**。

### 3.2 独立 profile + CDP 通路（可用）

```
独立 profile 起 headless + --remote-debugging-port
  → /json/version 连通（Edge 154 / CDP Protocol 1.3）
  → /json/list 返回 7 个可操作标签页
```

### 3.3 复用机制成立

用独立 profile 读一页 B站搜索结果页：

```
DOM 1,096,967 字节 ｜ 正文 5,557 字符 ｜ 耗时 8.5s
profile 里落下 Cookies 36,864 字节  ← 复用机制真的成立
```

### 3.4 风控检测是响的（正/负向都验过）

| 目标 | 返回体特征 | 探针行为 |
|---|---|---|
| B站搜索页（公开） | 正常 DOM | `exit 0`，输出正文 ✅ |
| 小红书 `explore`（匿名） | 标题即「安全限制」 | `exit 2` ⛔ |
| 抖音搜索（匿名） | 「验证码中间页」 | `exit 2` ⛔ |

**判风控看返回体特征，不看关键词**——B站页面正文里就写着「登录」「立即登录」，
那是它自带的按钮文案。上一轮就是这儿把一个可读渠道误判成了 `BLOCKED`。

### 3.5 踩到的坑：**「有 cookie」≠「已登录」**

第一次写完诊断，它报「已登录：B站、小红书、抖音」——**是假的**。
匿名访问同样会下发设备/风控 cookie，于是这些域就出现在 profile 里了。

**修法**：判登录态看**标志性 cookie 名**（`web_session` / `SESSDATA` / `sessionid` /
`SUB` / `z_c0`），不看「有没有 cookie」。修完立刻正确：
「访问过 B站、小红书、抖音 ｜ 已登录：无」。

> 这个坑和闸门设计是同一个道理：**判据必须落在「是不是」上，不是落在「有没有」上。**

### 3.6 还没验证的一件事（如实说）

**登录态下小红书/抖音到底能不能读到正文——本机没有验证过。**

因为验证它需要你**亲自扫一次码**（我不该、也不会代你登录）。已知的是：
匿名必被风控拦（3.4 已证）；登录后能否通过，取决于平台当时的策略与你账号的状态。
**在没验证之前，这条渠道的产出按「可能为 0」计。**

## 四、怎么用（三步）

```bash
PY="python <SKILL_ROOT>/tools/social_login.py"

# ① 自检：有没有浏览器、CDP 通不通、profile 建没建
$PY --check

# ② 扫码登录（**只此一次**）：会开一个独立窗口，不影响你日常浏览器
$PY --launch --site xiaohongshu     # 或 douyin / weibo / bilibili
#    登录完成后关掉那个窗口

# ③ 读一页（复用登录态，headless）
$PY --grab "<笔记或搜索页 url>" --out page.html

# 随时查状态
$PY --status
```

**边界**（脚本里写死了，不靠自觉）：

- **只读**：只 dump DOM。不点赞、不评论、不关注、不发帖。
- **不导出凭证**：从不读取/解密/写出任何 Cookie、Token、密码。
- **一次一页**：不做批量翻页、不做并发——**这是刻意的**，一旦自动化，风险就从「平台条款」升级到「你的账号被限」。
- **命中风控立即退出（码 2）**：不换 UA、不重试、不打验证码接口。

产出仍然要走 `social_notes.py` 校验，写进线索卡时
`connector_type` 记 `browser_logged_in`，并记 url 与查看时间。

## 五、GitHub 上有什么（本轮核实）

搜到的都**不是 WorkBuddy skill**，而是三类东西。列在这里是为了让你知道
「不是没人做过」，也为了知道**为什么本项目没有直接装**。

| 类型 | 代表 | 许可证 | 为什么没直接装 |
|---|---|---|---|
| 独立爬虫框架 | **MediaCrawler**（65,797 stars） | **NON-COMMERCIAL LEARNING LICENSE**（非 MIT） | ① 非商业许可；② 走签名对抗路线，与铁律 8 对冲；③ 要先装 Playwright + 扫码；④ 官方文档自己写明「会触发风控，遇验证须停手」 |
| MCP server | `mcp-xiaohongshu`、`dy-xhs-mcp-server`、`media-crawler-mcp-service` | 各异 | 都要扫码登录 + 本地执行代码；性质同 ③ 档，属「批量采集」强度 |
| 第三方商业 API | **TikHub**（含中国加速域、MCP 集成） | 商业服务 | 按次计费、仍是第三方聚合 → **`[C]` 封顶**，花钱也上不到 `[B]` |

**本机能不能装？** 实测：

```
github.com              → 超时（网页不通）
api.github.com          → 200 ✅
raw.githubusercontent   → 200 ✅
codeload.github.com     → 200 ✅（能下 tarball）
```

所以**能装，但要走 tarball / raw，`git clone` 会卡**。

> **要不要装？** 判断标准不是「能不能」，而是第二节那张表——
> 它给你带来的是 `[C]` 级线索，代价是账号风险 + 非商业许可 + 持续跟修。
> 如果你确实需要「几百条笔记做热度分析」，它是对的；如果只是做一份路书，
> **走官方渠道 + 搜索引擎索引 + 你自己刷到的那几条**，性价比高得多。

### 5.1 更省事的替代路径：浏览器插件（`xiaohongshu-mcp` 的 x-mcp 版思路）

上面三类都不理想，但**第五类**值得单独拎出来——**浏览器插件形态**：

| 形态 | 谁在跑 | 出口 IP | 登录态 | 账号风险 |
|---|---|---|---|---|
| 本包 AUTH 档（CDP + 独立 profile） | 本包脚本 | **本机** | 须扫码一次 | 落在你账号 |
| 服务器型 MCP / 爬虫框架 | 对方服务器 | **对方 IP** | 须扫码 | 落在你账号 + 服务器被风控 |
| **浏览器插件** | **你自己的浏览器里** | **你自己的真实 IP** | **复用你已登录的态** | 同「你自己多看几页」 |

**为什么这条更对**：本项目实测到的风控根因是 **IP 风险**（小红书返
`安全限制 · IP存在风险 · 300012`）——插件在用户自己的浏览器里运行，
**天然没有 IP 风险这条**，也不需要独立 profile 与二次扫码。

**为什么本包不内建它**：
- 它是**外部工具形态**，不属于「说明书 + 脚本」这套 skill 的交付面；
- 插件须装进浏览器、要用户自己信任其权限，**这一步的判断权必须在用户手上**；
- 与 CDP 路线**共享同一套证据口径**：即便走插件，拿到的仍是 `[C·单源]`，
  **不会因为渠道更顺就升等级**。

> **结论**：插件是「想省事时」的替代入口，不是「更可信的来源」。
> 本包不装它、不推荐具体插件名，只把这条路径如实登记在此——
> 你若要试，**风险自担，且产物照旧按 `[C·单源]` 处理**。

## 六、合规与账号风险（如实列，不美化）

**平台侧**
- 小红书/抖音等平台的用户协议普遍禁止「使用自动化程序批量获取内容」。
- **个人、非商业、小量**的浏览式读取，实际追责概率极低，但**不是零**。
- 本项目不提供任何绕过风控的手段，也不接受「换个 IP 再试」这类操作。

**账号侧**
- 强度 ② 的风险约等于「你自己多看几页」——主要风险是登录态过期要重扫。
- 强度 ③ 的风险是真实的：**限流、要求验证、极端情况封号**。而且牵连的是**你的主账号**。

**数据侧**
- 只记公开内容与公开账号 ID；**不采联系方式、不采行程轨迹、不采个人信息**。
- 摘录事实 + 署名出处，不整篇转载。
- 用第三方 API 时，合规责任在调用方，不得转售或公开原始数据集。

**最后一句**
这套东西的价值是「多几条线索」，不是「更可信的线索」。
**如果一条线索只能靠登录才拿得到，那它在证据体系里的分量，本来就不高。**
