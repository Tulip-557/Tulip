# 口碑可信度：评价、评论区、夸大与水军怎么处理

> 回答三个绕不开的问题：
> ① 路书到底有没有参考**别人的评价**？② 视频博主夸大、刻意美化怎么办？
> ③ 评论区的水军怎么识别？
>
> 机器可查：`social_notes.py --triangulate`（谁在说 / 独立来源数 / 原话并列）。

---

## 一、先说结论，包含不好听的那部分

**「多来源、多角度」不是靠采得更多，而是靠分清谁在说。**

本项目原来的社媒层只回答了「有什么可玩」，没回答「别人玩完觉得怎么样」。
2026-09-27 用中山那份真实线索卡实测（`--triangulate`），结果是：

```
地点 13 个：交叉印证 0 ｜ 单源 13
口碑构成：平台编辑/攻略站 3 ｜ 媒体机构 4
⚠️ 这批情报里没有任何真人评价或评论
```

**这是必须如实说出来的现状**：

| 想回答的问题 | 现在能答吗 | 卡在哪 |
|---|---|---|
| 有哪些点可玩、怎么串 | ✅ 能 | — |
| 官方/媒体怎么定调 | ✅ 能 | — |
| **去过的人觉得怎么样** | ⚠️ 只有攻略站编辑的转述 | 真人评价与评论区**基本没进来** |
| **13 个地点里哪些是共识** | ❌ 不能 | 每个地点只有一个来源提及，无从交叉 |

所以：**在补上真人评价之前，路书里不许出现「游客普遍反映」「大家都说」这类写法**——
那不是口碑，那是把机构口径包装成民意，比不写更糟。

## 二、「为什么读不到评论」：渠道决定论

评论区的可达性，**原以为比正文更差**（评论接口几乎都要登录态）。
2026-09-27 实测**推翻了一半**：**评论不一定要走接口——把页面滚起来读渲染结果就行**。

| 平台 | 正文 | 评论区 | 性质 |
|---|---|---|---|
| 小红书 | ⛔ 匿名被风控（`300012`） | ⛔ 更严 | 风控，不是登录墙 |
| 抖音 | ⛔ 匿名被风控（验证码中间页） | ⛔ 更严 | 同上 |
| 微博 | ✅ 公开可读（实测 93 KB / 147 块） | ⚠ 部分可见 | 移动版比 PC 版松 |
| B站 | ✅ 公开可读（实测 1.1 MB / 42 卡片，字段 42/42） | ✅ **可读，未登录即拿到部分正文** | 卡片元数据 + 详情页简介；**评论区需 CDP 滚动 + 穿透 45 层 Shadow DOM**（`tools/cdp_read.py`）；**口播仍拿不到** |
| 公众号 | ✅ 全文可读（实测 4.7 MB DOM） | ⛔ 无公开评论 | 官方发布主阵地 |
| OTA 攻略 | ✅ 可读 | ⚠️ 编辑精选为主 | 代表编辑部，不代表散客 |
| **用户投喂** | ✅ 最干净 | ✅ **真人评论最可靠的一手来源** | 用户自己刷到的那条 |

> **B站评论实测样例（2026-09-27，未登录）**：
> `我觉得煲煲掂的乳鸽就很好吃了` ｜ `中等偏上吧`（UP主回复）｜
> **`以前吃蛤蟆时就去，自从改左做吃鸽就去过一次，真系唔觉好吃`**（粤语差评）
> —— 同一批里正反两面都有，天然构成对照。这就是口碑层一直缺的那块。
> 未登录只渲染出 3/6 条（页面提示「登录后查看 6 条评论」），**够做定性判断**。

**这张表要读出的结论**：

1. **小红书/抖音的评论区，本项目拿不到**——那是风控加账号墙的双重拦截，
   按铁律 8 一次即停手，不绕。**报「没有」比报假的「有」值钱**。
2. **能拿到的评论主要是「用户投喂」**——用户把刷到的帖子连同评论截图发来，
   这是唯一既真实、又零风险的路径。所以采集时**要主动向用户要评论截图**，
   而不是只收正文链接。
3. **B站/微博的可读部分，信息密度低**：B站只能拿标题与简介（拿不到口播），
   微博短文本为主。它们更适合「话题发现」，不适合当口碑主体。

## 三、三个机器化的字段：谁在说 / 说了什么 / 值不值得信

### ① 谁在说（`voice`）——口碑层的地基

```
OFFICIAL  官方机构（文旅局 / 政府 / 协会）
MEDIA     媒体机构（日报 / 新闻网）
EDITOR    平台编辑 / 攻略站
CREATOR   内容创作者（博主 / UP 主）← **夸大风险最高**
TRAVELER  普通游客（正文自述）
LOCAL     本地人（自称）
COMMENT   评论区
UNKNOWN   判不出来（按最保守处理）
```

**身份决定了这条说法怎么用**：

- `OFFICIAL` + `MEDIA` 讲同一件事 → 两个独立来源 → 可到 `[B]`；
- `CREATOR` 说的**任何东西，在拿到第二个独立来源之前，都只是 `[C·单源]`**——
  它值不值得信不由内容决定，由**它有没有被别处印证**决定；
- `UNKNOWN` 按 `[D]` 处理，并在路书里给出人工确认方式。

> `_infer_voice()` 的推断是**保守**的：认不出就报 `UNKNOWN`，不硬塞身份。
> 赌错身份会让一条广告冒充官方口径，或把官方发布当成软广——两种错都比"不知道"更糟。

### ② 说了什么（`reviews[]`）——注意区分「正文自述」与「评论区」

```json
{"text": "周五晚上去的，停车位找了20分钟，建议早点到",
 "stance": "NEGATIVE", "source": "COMMENT", "account_hint": "老陈", "likes": 12}
```

- `source` 只能是 `NOTE`（正文自述）或 `COMMENT`（评论区）；
- `stance` 只能是 `POSITIVE` / `NEGATIVE` / `MIXED` / `NEUTRAL`——
  **机器不判语义，只登记立场**，判断由写路书的人做；
- `account_hint` 只记**公开昵称**，不记联系方式、不记行程轨迹。

**为什么评论比正文值钱**：正文是作者想让你看的，评论区是作者没控制的。
一条「停车位找了 20 分钟」的差评，比十句「绝美」有用得多。

> ⚠️ 评论区**同样受四条死线约束**。实测闸门已覆盖：评论里写「9 点开门」→ 拒，
> 「人均 50 元」未标 `price_signal` → 拒。**评论区不是法外之地**，
> 而且它比正文更常出现价格与时间——所以这条闸门实际命中率不低。

### ③ 值不值得信：夸大信号与水军信号

**这两样都只是「信号」，不是「结论」。** 原因很直接：

- 真心推荐的帖子也会写「绝美」「必去」——**词面上与软广分不开**；
- 真实用户也可能用默认昵称、也可能只写「不错不错」——**行为上与机器人分不开**；
- 平台自己都判不准水军，一个本地脚本更不可能。

**所以本项目的做法是「标出来，排后面看」，绝不是「判定并删除」**：

| 信号 | 判据（机器可判） |
|---|---|
| **夸大/推广词** | 命中 `绝美 / 天花板 / 全网最 / 必去 / 一天玩遍 / 出片神器 / 秘境` 等 35 个词表 |
| **空洞好评** | 只有泛化夸赞、无任何具体信息（无地点 / 数字 / 动作） |
| **批量雷同** | 与同批另一条评价相似度 ≥ 80%（整批复制的典型形态） |
| **批量账号** | 昵称呈默认特征（`user+数字`、纯数字后缀、`momo` 一类） |

实测（2026-09-27，构造样本）：3 条完全相同的评论 → 全部标 `water_suspect` 并注明
「与同批另一条评价高度雷同（相似度 100%）」；而「周五晚上去的，停车位找了 20 分钟」
**一条都没命中**——判据不误伤有细节的差评，这是它可用的前提。

> 每条可疑判定都会带上 `water_disclaimer` 字段。**别把它当结论引用**。
> 正确用法：「这 3 条雷同，先看别的 20 条。」

## 四、交叉印证：机器能可靠做到的那一半

`social_notes.py --triangulate` 按地点聚合所有来源，输出三件事：

```
✅ 孙文西路步行街　独立来源 2 ｜ 提及 2 ｜ 谁在说：MEDIA/OFFICIAL
    [MEDIA] zsrbapp.zsnews.cn
        ['南洋骑楼建筑群', '非遗巡游主线路'] / ['档期内的主会场，白天踩点、晚上才是正戏']
    [OFFICIAL] zsxwfbt.zs.gov.cn
        ['南洋风情旅游周主会场'] / ['双节档期的主阵地']
```

- **独立来源 ≥ 2 → `CROSS_CHECKED`**（判据是**不同域名**：同域转载不算两个来源）；
- **独立来源 = 1 → `SINGLE_SOURCE`**——**不等于错，只是还没人替你复核**；
- 各来源原话**并列摆出**，不做合并、不做语义裁决。

**机器做不了的那一半，必须说清楚**：本工具**不判语义冲突**。
「A 说必去、B 说没意思」这种矛盾，机器能检测到"两个来源提到同一地点"，
但**不能可靠判断它们是否互相矛盾**。所以冲突一律**并列呈现，由人读原话**，
按 `evidence-rules.md` 第 ④ 条「矛盾项并列」处理，**不擅自裁决**。

> 另一个刻意的取舍：地点名**只去空白、不做模糊合并**。
> 「孙中山故居」与「孙中山故居纪念馆」不会被合并——因为错合并会把两个地方的说法
> 混在一起，**制造出一个不存在的共识**。宁可漏合并，不可错合并。
> 代价是：中山的「孙文西路文化旅游步行街」与「孙文西路步行街 / 香山古城」
> 没有被合并（实测如此），需要人工看一眼。

## 五、操作口径：口碑三角

判断一个地点值不值得去，**要求三类口径各至少一条**，缺哪条就明写缺哪条：

```
① 机构口径  官方文旅 / 媒体的定调      → 回答「这是什么、什么档期」
② 编辑口径  OTA 攻略 / 深度长文        → 回答「怎么玩、动线怎么排」
③ 真人口碑  评论区 / 用户投喂 / 游记    → 回答「实际体验怎么样、有什么坑」
```

**只有 ① 没有 ③ 时，路书里必须写成「官方称…」，不能写成「大家都说…」。**
这是这套机制里最容易违反、后果也最严重的一条：把机构口径包装成民意，
比干脆不写口碑更糟——它给了读者一个假的安全感。

**视频/博主的处理**（用户特别担心的「夸大博流量」）：

1. 博主说法进路书前，**至少要有一个不同域名的来源罩住**，否则按 `[C·单源]` 标；
2. 命中推广词不等于内容为假，但**它说的"最/唯一/必"一律不写进路书**——
   这类词是主观强度，不是事实；
3. **拿不到口播就不许转述口播**。B站实测只能拿到标题与简介，
   所以「UP 主说这里人少」这种话**不许写**——那是在虚构你根本没读到的内容。

## 六、诚实边界（写在这里是为了不被问倒）

1. **水军识别不可靠**——只能给信号，任何"已识别水军 N 条"的表述都是过度承诺；
2. **语义判断不可靠**——立场（正面/负面）是人工登记的，不是机器判的；
3. **评论覆盖有限**——小红书/抖音评论区本机不可达；能拿到的以用户投喂为主；
4. **`promo_flags` 不是质量判断**——官方稿也会用「精品线路」这类词；
5. **跨源印证稀少是常态**——中山实测 13 个地点交叉印证 0 个。
   **这本身是有价值的信息**：说明这批情报还停留在"官方定调 + 编辑整理"，
   真人体验层是空白的，路书的写法必须与这个事实相符。
