# 双版本：同一事实源，两份路书

```
路书_XX_事实源.json ─┬─ render_html.py             → 路书_XX.html         （完整版 · 策划件）
                     └─ render_html.py --compact   → 路书_XX_精简版.html   （精简版 · 执行件）
```

**两版共用同一骨架**：CSS 指纹、IA、导航、30 项自查口径完全一致。精简版**不是另一套模板**，
`consistency.py` 与 `ludbook_check.py` 照跑，全绿才算交付。

---

## 一、先说结论：精简版曾经"瘦不下来"，原因不是机制错，是分寸错

2026-09-27 实测中山（完整版 14072 字）：

| 版本 | 可见字数 | 占完整版 |
|---|---|---|
| 改版前 | 13651 | 97% |
| 第一轮（只补 slot 双档 + 压 sections 文案） | 11617 | 83% |
| 第二轮（资料区不再渲染正文） | 8776 | 62% |
| 第三轮（摘掉 slot 里的玩法细节） | 7939 | 56% |
| 第四轮（删掉本行程用不到的条目） | **7782** | **55%** |

> ⚠️ **口径**：上表是**探针口径**（只数各 `section` 正文的可见字符，不含首屏速览表）。
> `compact_check` 的 C5 用**全文可见字数**口径，同一份产物读出来是
> 完整版 14072 字 → 精简版 **7837 字（55.7%）**。两个口径都可复现，
> **引用时务必写清是哪一个**——否则「同一件事两个数」会自己把自己变成不可信来源。

改版前的根源有两条，都是**设计判断**问题，不是代码问题：

1. **以为 `sections` 是主体，其实 `days` 才是**（`days` 占约 65%）。
   旧机制只给 `sections` 做了双档，**`days[].slots` 根本没有双档能力**——
   占三分之二的正文一分没减，全篇当然只省 15%。
2. **把「不删信息」当成了美德**。旧设计用 `<details>` 折叠资料区，并写下
   「内容一个不删，只是不占首屏」。但 `<details>` 只是把内容**移出首屏**，
   字数与 DOM 长度一分未减；更糟的是它和渲染器自己的承诺相矛盾——
   `build_quickview` 对读者写的是「本页没有的东西（住宿比价、预算逐项、备选点、
   特产细节）都在**完整版**里」。**声明与实现必须一致**。

现在的定位一句话：**精简版是执行件（路上照着走），不是阅读件。**

## 二、三档削减机制

| 档 | 机制 | 谁负责 |
|---|---|---|
| ① 文案双档 | `sections.<k>` 写 `{"full": …, "compact": …}` | 人写 |
| ② 时段双档 | `days[].slots[].body` 写 `{"full": …, "compact": …}`（**新增**） | 人写 |
| ③ 资料区不展开 | `compact` 档就写**一行「本版不展开」指引**，正文不进精简版 | 人写，机器查 |
| ④ 逐日注释 | `food` / `stay` / `warn` 展开；`metro`（今日交通汇总）收进 `<details>` | 机器 |

**① 与 ② 是同一套机制**（同一个 `_pick_section`）。
两档写在**同一个字段里**是刻意的：分成两份文件必然"改了这边忘了那边"。
没写 compact 档的单元，渲染器会沿用 full 并打印清单——但**提醒拦不住交付**，
所以 `compact_check.py` 把它变成可判 FAIL 的指标。

**③ 的名单**（数据在事实源里，不在渲染器里）：

| 板块 | 精简版里的形态 |
|---|---|
| `stay` 住宿 | 一行指引（每晚住哪见各日卡片） |
| `cost` 预算 | 一行指引 + 保留总数与人均 |
| `eat` 美食清单 | 一行指引（定档店见各日卡片） |
| `gift` 特产送礼 | 一行指引 + 保留最近一家店名地址 |
| `boost` 备选点 | 一行指引 |

**仍展开**：`overview` `drive` `ticket` `tips` `sos` —— 判据是**「出事/当天要用」还是「出发前翻一次」**。
`_FOLD_IN_COMPACT` 现为空集（留作挂点），因为 `<details>` 已被实测证伪。

## 三、`compact` 档怎么写（人写规则）

**保留**：

- 时间点、地点（含门牌号，`ludbook_check` ⑩ 要数）、怎么去（方式 + 车程 + 距离）
- 花多少、开放状态、预约状态
- **强制约束**：末班 / 最晚 / 截止 / 停止入场 / 退房 / 寄存 / 需提前 / 留足余量 / 立刻
- ⚠️ 项、证据徽章 `[A]`–`[D]`、来源与**查询时戳**
- 行程时长（今天留 2 小时 / 只给 75 分钟）

**删掉**：

- 评价、感受、典故、"为什么值得去"
- 出片点清单、动线玩法、榜单名次、活动方阵名单
- 备选加站、本行程用不到的条目（如儿童/老人优惠票）
- 铺陈性的理由句（"今天比常规提前开饭，是为了…"）

## 四、闸门：`tools/compact_check.py`

```
python tools/compact_check.py --facts 路书_XX_事实源.json \
    --full-html 路书_XX.html --compact-html 路书_XX_精简版.html
```

| 规则 | 判什么 | 不绿的阈值 |
|---|---|---|
| C1 双档覆盖 | `sections` 与 `slots` 是否都写了 compact 档 | 一个都没写 = FAIL；缺档 = WARN |
| C2 逐段精简度 | full ≥ 200 字却压不到 90% | WARN（点名到单元） |
| C3 约束不丢 | full 里含强制约束词的**数字**是否活到同一条 compact | FAIL |
| C4 证据不降级 | full 有证据标记、compact 一个都没有 | FAIL |
| C5 产物精简率 | 精简版正文 / 完整版正文 | > 60% FAIL；> 55% WARN |

退出码：有 FAIL 时 2（与 `evaluate` / `source_audit` 同一纪律）。零第三方依赖，可进 CI。

## 四点五、写作期助手：`tools/compact_draft.py`（半自动草稿，2026-09-30 落地）

2026-09-28 曾把「compact 半自动草稿」列入暂缓（理由：自动压缩必丢约束数字，
收益 30% 但会坏掉证据链）。落地版按「消除顾虑」而不是「无视顾虑」实现：

```
python tools/compact_draft.py --facts 路书_XX_事实源.json --out 草案.json
```

- **只出草案副产物，永不写事实源**——机器打底、人来核对、人自己合入，
  合入后 compact_check 终审（草案不等于达标）。
- **保守抽取**：任何带数字 / 方括号（徽章或注记）/ 粗体 / 约束词的段一律保留；
  可删的只有纯叙述段，且连其中的数字一起列进 `dropped` 清单供人工核对。
  C3 的教训变成结构保证：约束段根本不进删除通道。
- **输出前跑不变量自检**（徽章不丢、约束数字不丢），违者退出码 2——那是工具 bug。
- 精简率（C2/C5）它管不了：草案往往还偏长，压措辞是人的活——「换写法而非
  压措辞」的分工没变：机器保证「删的不可能是约束」，人负责「删到够短」。

> **中山现状：C5 = WARN（55.7%，恰在 55% 线上方）。** C1–C4 全 PASS，`FAIL 0` → 合格。
> 这条 WARN **如实留着、也不去挪阈值**——为了让自己变绿而调阈值，就是刷分，
> 和这个项目拒绝「分数会诱发刷分」的立场冲突。它现在的用途是「下一版还能再瘦一点」的提示。

### 判据取向：宁松勿噪

C3 的词表**刻意收窄过一次**。初版含「提前 / 当天 / 最后一班」，结果把
「今天比常规提前开饭，是为了给夜游留出整段（换乘缓冲 15 分钟之后还要 21 分钟车程）」
这种**排程理由句**也当成约束句——那是解释，删掉不算丢东西。
另外 C3 **只查 `slots`**：`sections` 是资料区，同一事实可能跨段出现，按单元查必然误报。

> **误报比漏报更伤**：满屏假警报，人第二次就不看了。

## 五、踩过的三个坑（都写进了闸门）

1. **压缩会悄悄丢掉来源时戳**。中山实测：删掉 `tips` 段里唯一那句
   「查询于 2026-09-27」，段内两条 `[A]` 立刻从 WARN 升级为 **FAIL**——
   `source_audit` 的 E2 允许"slot 级继承"，但继承源被删掉就无从继承了。
   **教训：compact 档要自己带时戳，不能只靠继承。**
2. **有意的留白不是降标准**。资料区按设计不展开，`compact` 里自然没有徽章。
   C4 因此跳过含「本版不展开」字样的单元——否则闸门会一直报假 FAIL。
3. **负向样本本身也会造假绿**。C3 的第一版负向样本是按时长/时刻正则去抹数字，
   结果选中的那个槽位 `compact` 里压根没有该数字，**注入等于没注入**，
   跑出来 `EXIT=0` —— 一度被误读成「C3 有洞」。
   改法是让样本**按规则自己的判据定位**（复用 `CONSTRAINT_RE` / `NUM_RE`
   找出「full 里有约束句且含数字」的槽位，再把该槽 `compact` 的数字整体抹掉），
   并且**注入后要用规则自己复核样本确实变坏了**。
   > **规则拦不住 ≠ 规则有洞，也可能是样本没造坏。两者必须分开验证。**

   现在四个负向样本各自只注入一类真缺陷，全部 `EXIT=2`：
   C1 抹掉全部 compact 档 / C3 抹掉约束句数字 / C4 抹掉 compact 的徽章 /
   C5 拿完整版 HTML 冒充精简版（精简率 100%）；中山真实样本 `EXIT=0`。

## 六、交付时怎么说

两版一起给，并说清**哪版什么时候用**：

> 「路上照着走用精简版；查价格、翻备选、比住宿的时候开完整版。」

精简版在 `<title>`、页脚与首屏三处都标了「精简版」——两版会同在一个手机里，
打开时必须一眼知道手里是哪一版。
