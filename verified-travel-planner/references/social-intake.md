# 社会情报采集 · 默认能力，不是可选项

> 对应 **阶段 3.5**。触发：**每个目的地默认执行**（跳过须声明，见 §1）。
> 工具：`tools/social_notes.py`（归一化 + 死线校验 + 增量合并）。
> 数据契约见 `data-contracts.md` 的 Social Research Result 与第八章。

---

## 一、它在架构里的位置

```
阶段 3   实查复核        → 硬数字：车程 / 票价 / 营业时间 / 余票       [A]
阶段 3.5 社会情报采集    → 玩法 / 体验 / 机位 / 时机 / 人流          [B]/[C]
```

**两根扁担各挑一头，信息不重叠、证据不互相顶替、死线不互相越界。**
阶段 3 回答「在哪、多远、多少钱、几点开」；阶段 3.5 回答「去了该干嘛、什么时候去最好、
值不值得多待」。后者是地图 API 一条都给不了的——所以它不能是可选项。

**为什么敢默认化**：三条死线把它与 A 级数据彻底隔开——社区知识只能**塑造路线**，
永不作**事实**呈现。越界风险由 `social_notes.py` 机器拦住，不靠自觉。因此它可以
每次都跑，而不会污染路书的可信度。

### 触发器与跳过条件

| 情形 | 动作 |
|---|---|
| 默认 | **跑**：产出线索卡 → 追加情报库 → 把声明写进 `meta.social_intel` |
| 纯过境（目的地停留 < 半天） | 可跳过，**须写明理由** |
| 用户明说不要社媒内容 | 可跳过，**须写明理由** |
| 目的地无公开内容（无人区 / 私人领地） | 可跳过，**须写明理由** |

> **跳过允许，静默跳过不允许。** 声明落在 `meta.social_intel`，渲染器把它变成
> `#overview` 顶部的「情报来源」条，交付自查第 **㉗** 项就查它。
> 判据是**留痕**而不是**必须采到**——「报『没有』比报假的『有』值钱」。

## 二、先看实测：直连社媒平台**不可行，而且不该绕**

2026-09-27 本机实测（无头 Edge 匿名，未登录、未带任何 Cookie）：

| 目标 | 结果 | 性质 |
|---|---|---|
| 小红书 首页 `/explore` | `安全限制 · IP存在风险，请切换可靠网络环境后重试 · 300012` | **风控拦截** |
| 小红书 搜索页 | 同上 | 风控拦截 |
| 小红书 笔记详情页 | 同上 | 风控拦截 |
| 抖音 搜索页 | `验证码中间页` | 风控拦截 |

**关键判读**：这两个页面都是**风控页，不是登录墙**。所以「登录一下就能读」是错的——
按铁律 8，遇风控**一次即停手换路径**，不重试、不换 UA、不绕。

> 这条是**试过之后**的结论，不是猜的。项目里正好有一条旧教训：
> 当年「还没试就断定小红书必须登录（确实是，但那是猜中的）」——
> 猜对了不算数。**每个「不行」都要有一次真试过的记录。**

## 三、三条路径 = 可复用来源清单（按可靠性降序）

> **这三条是「怎么走」；「哪几条走得通」在 `social-sources.md`**——那里有 21 条渠道的
> 五档能力矩阵（`OPEN` / `OPTIONAL` / **`AUTH`** / `GATED` / `BLOCKED`）与五条扩展路径。
> **「我登录一下能不能读」单独一页**：`references/social-login.md`。
> 机器可查：`python <SKILL_ROOT>/tools/social_source.py --doctor`。
> 三条路径是**最小可用集**（零配置即可跑），扩展渠道都是在这三条之上做加法。

### ① 官方文旅发布 ← 首选，可到 `[B]`

政府文旅部门、旅游协会、主流媒体发布的**榜单与精品线路**。实测（中山，2026-09-25 发布）
能拿到：十大热门景区、八条精品线路的完整串联、节庆活动、业态说明。

- **为什么值钱**：它给的是「线路组合 + 玩法定性」，恰好完全不碰死线
- **怎么标等级**：官方机构发布 + 媒体转载 = 两个独立来源 → `[B]`
- **怎么找**：搜「<目的地> 文旅 精品线路 / 十大景区 / 官方推荐」
- **记录口径**：`connector_type` 仍填 `web_search_fallback`（是搜到的），
  但 `platform` 写机构名（含「文旅 / 旅游局 / 旅游协会 / 日报 / 新闻网」等词）
  ——`social_notes.py` 靠这一列给 `[B]` 建议

### ② 搜索引擎索引 ← 兜底，`[C·单源]`

`connector_type = web_search_fallback`。实测能拿到攻略站文章的**完整正文**
（逐日安排、餐厅名、玩法描述），这是索引页给不了的。

- ⚠️ **索引到的摘要不是第二来源**。它和原文是同一来源，不能互相印证——
  这是「两个来源其实是同一篇内容的转载」的典型形态
- ⚠️ **AI 摘要只当线索**（实查纪律第 4 条），写结论前要落到具体页面

### ③ 用户投喂 ← 最贴近真实，`connector_type = user_provided`

用户刷到好内容，把**链接或截图**发来。信源名单（`sources.md`）就是为这条路设计的。

- **为什么可靠度反而高**：真实用户在真实网络环境下能打开，你打不开的页面他能打开
- **为什么仍需降级**：仍是单源 UGC → `[C·单源]`，且必须记清平台与账号 ID
- **截图**：从图片读出的说法要带 `"extraction": "image"` 与图片序号；
  小红书是图片优先的平台，**只读文字的笔记等于没读过**（逐日行程图、费用明细表都在轮播图里）

## 三·五、口碑层：谁在说，比说了什么更要紧

> 完整方法论见 `references/social-credibility.md`。这里只讲**动作**。

采到内容只是第一步。**同一句话，文旅局说的、攻略站编辑写的、博主拍的、评论区留的，
分量完全不同**——所以每条线索都要登记 `voice`（谁在说）：

```
OFFICIAL 官方机构 ｜ MEDIA 媒体 ｜ EDITOR 攻略编辑
CREATOR 内容创作者（夸大风险最高）｜ TRAVELER 游客自述 ｜ LOCAL 本地人 ｜ COMMENT 评论区
```

**三个必做的动作**：

1. **先看口碑构成**——`social_notes.py` 跑完会打印 voice 分布。
   若 `TRAVELER / LOCAL / COMMENT` 全为 0，说明这趟只拿到机构与编辑口径，
   **正文里就不得出现「游客普遍反映」「大家都说」**。这条会被渲染器自动提醒。
2. **要评论区**——小红书/抖音评论区本机不可达（风控），能拿到的真人评论主要靠
   **用户投喂截图**。所以采集时**主动向用户要评论截图**，别只收正文链接。
   `reviews[]` 每条记 `text / stance / source(NOTE|COMMENT) / account_hint`。
3. **跑交叉印证**——`--triangulate` 按地点列出「独立来源数 / 谁在说 / 各来源原话」。

```bash
PY="python <SKILL_ROOT>/tools/social_notes.py"
$PY --input 社媒线索_XX.json --triangulate        # 多来源交叉印证
```

判据：**独立来源 ≥ 2（不同域名）才算交叉印证**；= 1 是 `SINGLE_SOURCE`——
**不等于错，只是还没人替你复核**。机器只做并列，**不裁决冲突**，矛盾项人工读原话。

**博主/视频的特别处理**（防「夸大博流量」）：

- `CREATOR` 说的任何东西，**拿到第二个独立来源之前一律 `[C·单源]`**；
- 命中推广词（绝美 / 天花板 / 全网最 / 必去 / 一天玩遍 等）会被记进 `promo_flags`
  ——**这是信号不是判定**，真心推荐也会用这些词，只用于「先看别的」；
- **拿不到口播就不许转述口播**：B站实测只有标题与简介，
  所以「UP 主说这里人少」这种话不许写，那是在虚构你没读到的内容。

> 水军信号（空洞好评 / 批量雷同 / 默认昵称）同理：**标出来排后面看，不判定不删除**。
> 每条可疑判定都自带 `water_disclaimer` 字段，引用时别把它当结论。

## 四、死线：这些东西**任何情况下**都不许从社媒进路书

| 禁止 | 为什么 | 去哪取 |
|---|---|---|
| 门票价、人均 | UGC 说的价格是**一条信号**，不是票价 | 官方渠道 / OTA 在售页 |
| 营业时间、开放时间 | 平台信息常年不更新 | 场馆官网 / 高德 POI |
| 车次、余票、列车与航班时刻 | 实时字段，抄来即过期 | 12306 / 航司 |
| 距离、车程 | UGC 里「打车 20 分钟」全不可采信 | 高德路线 |

**允许进路书**（且必须带出处）：
玩法建议、路线顺序假设、人流体感、季节时机、体验描述、机位、注意事项。

> 这不是在丢社区知识——**恰恰是它让社区知识全部都能用上**。
> 一条记为「假设」的说法可以塑造路线，同时从不会作为事实呈现给旅客。

## 五、三份可复用资产（每趟都要回流）

情报不是用完即弃的检索结果，是**跨行程滚雪球的数据资产**。
这是「结合社媒生成攻略」从一次性动作变成**持续提升质量**的关键。

| 资产 | 位置 | 谁写 | 下次怎么用 |
|---|---|---|---|
| **线索卡** | `社媒线索_<目的地>.json` | `social_notes.py -o` | 先读旧卡看还差什么、只补新增；`--merge` 增量并入 |
| **玩法情报库** | `情报库/玩法情报_<城市>.md` | 阶段 6 复盘时追加 | 下次去同城 / 邻近城市**先读它**，不重搜已知结论 |
| **信源名单** | `references/sources.md` | 途中刷到靠谱内容就补 | 直接成为下一趟的采集起点 |

### `--merge`：复用是怎么变成机器动作的

```bash
social_notes.py --input 新线索.json --merge 旧线索卡.json -o 线索卡.json
```

- **去重键 = `url`**（无 url 退化为标题）：本次重采到的用新条目，旧的丢弃；
- 旧卡里本次**没采到**的**保留**，标 `carried_over: true`；
- 沿用条目按时效判：超过 `--stale-days`（默认 90）或从无时戳 → 再加 `stale: true`；
- 输出带 `coverage` 块：`new / carried_over / stale / duplicates_dropped / by_level / connector_types`。

> **保留而不清空，是这一步存在的理由**——清空就等于每趟从零开始，
> 那「持续积累」只是句口号。但沿用条目也**绝不会冒充新鲜情报**：超期的会被点名，
> 下次开工会先重核。合并后的整卡会**再走一遍死线校验**——
> 「上次写对了所以这次不查」是这套规则最不能接受的心态。

### 玩法情报库的追加格式

```markdown
## <城市> · <YYYY-MM> 更新

- **<地点>**（`[B]` 官方文旅发布 2026-09-25 / `[C·单源]` 攻略站）
  - 玩法：<怎么玩、什么时段>
  - 机位 / 时机：<光线、季节、人流>
  - 已知坑：<如有>
  - 来源：<url>（核实于 YYYY-MM-DD）
```

只沉淀**跨行程仍然成立**的东西（玩法、时节、机位、避坑）。
会过期的（票价、档期活动）留在线索卡里，靠 `checked_at` 管时效。

## 六、每趟的标准动作（SOP）

```bash
CLI="python <SKILL_ROOT>/tools/travel_planner.py"
PY="python <SKILL_ROOT>/tools/social_notes.py"
SRC="python <SKILL_ROOT>/tools/social_source.py"

# -1 定渠：先看这台机器上哪几条路走得通、证据天花板多高，再决定这趟铺多大
$SRC --doctor
$SRC --plan XX --days 3 --month 9月      # 生成关键词组与渠道顺序，不用每次现想
#    渠道层细节（21 条渠道五档矩阵 / 五条扩展路径 / 合规·反爬·解析）见 references/social-sources.md

# 0 复用：先读旧卡与情报库，明确「这次只需要补什么」
$PY --input 社媒线索_XX.json --json          # 看旧卡里已有的（超期的就是重核重点）
cat 情报库/玩法情报_XX.md                    # 看沉淀结论

# 1 采集：按三条路径搜，写成线索草稿
#   每条笔记必须有：url / checked_at / connector_type（来源要自报）

# 2 校验 + 增量并入（一次完成：去重、标超期、重跑死线）
$PY --input 新线索.json --merge 社媒线索_XX.json -o 社媒线索_XX.json
#   注：读取在写盘之前完成，所以「--merge 与 -o 指向同一份」是安全的；
#       想保底就 -o 到临时文件，核对无误再覆盖。

# 3 口碑体检：谁在说 + 多来源交叉印证（缺真人评价会被点名）
$PY --input 社媒线索_XX.json --triangulate
#   看两个数：① 口碑构成里 TRAVELER/LOCAL/COMMENT 是否 >0；
#             ② CROSS_CHECKED（独立来源 ≥2）有几个。都没到就先别写「口碑」二字。

# 4 汇编成景点卡，喂下一环
$PY --input 社媒线索_XX.json --brief
$CLI compile-research --input 归一化.json

# 5 声明：把采集结果写进事实源 meta.social_intel（渲染器会自动注入 #overview）
#   voices 直接抄 coverage.voices——它决定正文能不能写「游客普遍反映」
```

退出码：`0` 通过 ｜ `1` 执行出错 ｜ `2` 有必须改的错（**改完再进管线**）。

### 归一化时会自动拦下什么

`social_notes.py` 把三条死线做成机器判定，**不靠自觉**：

- 证据类别不在契约的六种里 → 拒（类别决定这条线索能走多远，自创等于绕过那张表）
- 价格写进 `PRICE_SIGNAL` 以外的类别 → 拒
- `PRICE_SIGNAL` 没标未核实 → 拒
- 写了营业时间（含「8:30 开放」「9 点开门」这类带时刻的说法）→ 拒
- 写了车次 / 余票 / 时刻 → 拒
- 缺 `url`（无法回溯）/ 缺 `checked_at`（不知何时查的）/ 缺 `connector_type`（不自报来源）→ 拒
- **评论区与正文同一标准**：`reviews[].text` 里写营业时间、车次余票 → 拒；
  出现具体金额而未标 `price_signal` → 拒（「价格还行」这类感受不算，
  「人均 50 元」这类断言才算——判据刻意收窄，避免噪声把闸门逼成摆设）
- `reviews[].stance` 不在 `POSITIVE / NEGATIVE / MIXED / NEUTRAL` 里 →
  拒（立场由人登记，机器不判语义）

> 判据边界（实测过的）：`CLOSURE` 允许「周一闭馆」（当天状态，契约列为可用类别），
> 但 `17:00 闭馆`（带时刻）会被拦。`10:00 开始游览` 属行程安排，不误伤。

### 景点卡必须完整

`compile-research` 出来的卡片，缺 `features` / `why_visit` / `suggested_duration_minutes` /
`source_refs` 任何一项都**不完整，不能进路线**。缺了先补，别指望渲染器替你补。

## 七、等级怎么定（写完路书要挂徽章）

| 来源 | 建议等级 | 理由 |
|---|---|---|
| 官方文旅发布 + 媒体转载 | `[B]` | 两个独立来源一致 |
| 攻略站文章（索引而来） | `[C·单源]` | 索引摘要不是第二来源 |
| 用户投喂的链接/截图 | `[C·单源]` | 未经工具实证 |
| 命中信源名单的账号 | 仍是 `[C·单源]` | **名单不是证据**，只是更值得交叉验证 |

`social_notes.py` 会在输出里给每条笔记一个 `evidence_hint`——那是**建议不是结论**，
最终仍按 `evidence-rules.md` 判。**宁可标低不标高**。

## 八、与只读边界（铁律 8）的关系

- ✅ 可以：读公开页面、读搜索引擎索引、读用户提供的链接与截图
- ❌ 不可以：绕验证码 / 登录墙 / 风控；导出 Cookie 或 Token；代替用户登录；

  这是铁律 1 的常规出口，不是失败

## 九、实测范例

中山真实情报（用上述路径① ②拿到，经 `social_notes.py` 归一化后 **7 条线索**，`coverage` 报
`B4·C3`；线索文件已随示例归档，见 git `3d1b73a`）。

**它真的改写了路线**（这是「默认能力」的意义所在）：中山 v2 的三处新增全部来自这里——
D1 孙文西路「南洋风情旅游周」夜游（档期 9/27–10/8 正好覆盖行程日期）、
D2 崖口东堤日落与海边夜市、D3 曹边村侨乡古村；来源结构从「高德一家 76%」
扩到含 4 条官方文旅发布 `[B]`。

**跨源一致性验证（意外收获）**：某攻略站给的崖口动线是
「稻田 → 村内吃饭 → 集装箱咖啡 → 燕石围红树林 → 东堤等日落 → 夜市」，
与按高德车程反推排出的顺序几乎一致——两条独立路径互相印证，排法站得住。

反向验证同样做过：故意违规的 9 项（营业时间混进体验类、票价写进 `EXPERIENCE`、
自创类别、无 URL 等）**全部被拦下**——闸门响不响，是验过的，不是假定的。
