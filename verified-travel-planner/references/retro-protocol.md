# 复盘回流协议（retro-protocol）

> 定位：把「踩坑 → 记录 → 规则化 → 负向样本」的闭环从**靠自觉**变成**有触发条件、
> 有固定模板、有出口判定的流程**。它不是新工具，是把已经在发生的事情（experience.md
> 的沉淀、闸门规则的逐条增补）正式化，堵住漏网（`desource.py` 那条「从来跑不通的
> 文档命令」就是写完两个月才被发现的漏网）。

---

## 一、触发条件：事件触发，不是每次生成都触发

**全绿的一轮没有经验可言，只有噪声。** 只有以下四类事件触发复盘：

| # | 事件 | 判据（机器可认） |
|---|---|---|
| 1 | 可行性被否 | `travel_planner.py evaluate` 退出码 2（`INFEASIBLE`） |
| 2 | 源核验拦截 | `source_audit.py` 有 FAIL（退出码 2） |
| 3 | 精简版被压坏 | `compact_check.py` 有 FAIL（退出码 2） |
| 4 | 交付后被用户打回 | 用户明确否定某项产出（人工判定，唯一非机器判据） |

全绿交付不触发。正向跑通只说明闸门没拦，**不产生新经验**。

## 二、复盘模板：结构化六字段，不是自由文本

每条复盘按此模板追加进 `references/experience.md` 的「本机记录」区：

```markdown
### <日期> <一句话标题>（<事件类型 1-4>）
- **现象**：机器报了什么 / 用户说了什么（原样，不转述成结论）
- **根因**：定位到哪一层（事实源写法 / 工具规则 / 文档 / 环境）
- **触发条件**：什么情况下会再犯（越具体越好，泛化的根因是错的根因）
- **目的地特定**：是 / 否——「崖口东堤适合看日落」是事实，不是教训
- **出口**：三分支之一（见下节），写明去向
- **提交号**：本次修复的 git commit（可追溯）
```

**字段缺一不算完成**。「根因」一栏禁止写「下次注意」——那是没有根因。

## 三、出口三分支：每条教训必须有去向

复盘出的教训，出口**二选一或三**，不允许悬空：

| 分支 | 判定 | 去向 | 验证 |
|---|---|---|---|
| ① 目的地特定 | 教训换个城市就不成立 | 事实源 / `情报库/玩法情报_<城市>.md` | 属于数据，不属于经验 |
| ② 可规则化 | 能写成机器判定 | 对应闸门（`source_audit` / `compact_check` / `ludbook_check`…）的 RULES + **一个负向样本** | 负向样本必须 EXIT=2——没被证明会报错的闸门等于没有闸门 |
| ③ 写不成规则 | 机器判不了（排版审美、文案分寸…） | `experience.md` 该条目末尾标 **`[人工维持]`** | 明示这是自觉区，不冒充已被机器接管 |

**不允许的第四种出口**：只写进文档散文里就当完事。`desource.py` 文档命令错误
存在了两个月，就是因为它悬在散文里，没有触发条件、没有负向样本。

## 四、LLM 的角色边界：起草不裁决

复盘可由 LLM 起草（现象/根因初稿），但**三个环节必须人仲裁**：

1. **根因是否成立**——LLM 会把偶然当规律（「中山门票标 `[C]` 违规」≠「门票都别标 `[C]`」）。
   错误经验进了生成链路是负反馈放大，不是改进。
2. **是否目的地特定**——这是 ①/② 的分岔口，判错整条教训进错库。
3. **是否可规则化**——LLM 倾向于说「能」，但写不出的规则硬写会变成误报闸门
   （C3 词表过宽的教训就在眼前）。

## 五、健康度自指：`[人工维持]` 是堵塞信号

`validate_skill.py` 盯着 **`experience.md` 里 `[人工维持]` 的条目数**，
与本协议的基线数交叉验证。这个数**只升不降 = 规则化通道在堵塞**——教训越积
越多却没变成闸门，说明分支②的「可规则化」判定被人偷懒跳过了。

处理纪律：每累积 3 条 `[人工维持]`，强制做一次「能否升格为规则」的专门复盘；
确实写不成规则的，在条目里写明为什么（「试过写成 C3 规则，词表必然误报排程句」
是合格理由，「还没想好」不是）。

当前基线：`[人工维持]` 0 条（2026-09-28 协议设立时）。

## 六、明确不做（与「每次生成后自动总结」设想的差别）

- **不做每次生成的自动总结**——全绿轮次产生的是噪声和错误泛化，经验库膨胀后
  检索精度和注入成本都劣化。
- **不做自由文本经验库**——自动生成的自由文本绕开了 `--scan` 的计数锚定，
  写法漂移会让机器校验失明（「写法一变规则就瞎」是本工具的既有教训）。
- **不做自动写文件**——复盘落盘由人执行（CRLF / 字节级基线的坑，自动写比人写更容易踩）。
