# 路书事实源（ludbook.json）字段规范

## 为什么要一份 JSON

上游见好把 HTML 骨架固化下来，但落地方式是「复制骨架 → 手改 4 类常量 → 手填 13 个区块」。
它自己在 SKILL.md 里写明理想态是**数据与模板分离**——本 skill 把这一步补上了：

```
单一事实源 ludbook.json ──render_html.py──▶ 路书_XX.html
```

好处是三条错误从「靠提示词祈求」变成「结构上不可能发生」：

| 老做法会犯的错 | 现在为什么不会 |
|---|---|
| 漏改占位符，成品里留着 `【目的地】` | 渲染器要求每个占位符都有值，缺值直接拒绝产出 |
| 侧栏导航漏了 `#drive` 入口 | 导航由骨架带入，不重写 |
| 改了 HTML 忘了改底稿，两边说法不一致 | HTML 是派生物，不手改 HTML；改就改 JSON 重渲染 |
| 换城市时 localStorage 键串味 | 城市码统一注入，字号键与勾选键强制同前缀 |

**硬规矩：JSON 是唯一事实源。HTML 不许手改——改了会在下次重渲染时丢失。**

## meta：全局常量

| 字段 | 必填 | 说明 |
|---|---|---|
| `destination` | ✅ | 目的地，出现在 `<title>`、侧栏页头、页脚 |
| `city_code` | ✅ | **2–8 位小写字母**，如 `cd`、`ls`、`hz`。用于 localStorage 键前缀，各城市必须不同 |
| `origin` | ✅ | 出发地 |
| `date_range` | ✅ | 日期区间文字，如 `2026-10-01 ~ 2026-10-03` |
| `party` | ✅ | 人数结构，如 `2 人 · 情侣` |
| `verified_date` | ✅ | 联网实查日期，页脚会显示「信息 X 联网实查」 |
| `nights` | ✅ | `N 天 N 晚` |
| `trip_theme` | ✅ | 行程主题，页脚用 |
| `photos_note` | ✅ | 逐张说明配图是实景还是示意。**示意项必须在 caption 里标「示意」** |
| `photos_source` | | 图源名，页脚用 |
| `sketch_note` | | 有自绘示意图时写「非等比例、仅供参考」 |
| `variant` | | `friend`（默认，单 `<style>`）或 `self`（保留 `#intel`，须自带第 2 块 `<style>`） |
| `title` | | 缺省为「<目的地>路书」 |
| `social_intel` | | 社会情报采集声明（阶段 3.5）。**强烈建议填**——不填则交付自查 ㉗ 红灯 |

### `meta.social_intel`：情报来源声明

社会情报采集是阶段 3.5 的**默认动作**，所以交付物里必须留下痕迹。渲染器会把它
变成 `#overview` 顶部的一条「情报来源」，第 ㉗ 项自查就查它。

```json
"social_intel": {
  "status": "COLLECTED",
  "paths": ["官方文旅发布", "搜索引擎索引"],
  "notes_file": "社媒线索_中山.json",
  "note_count": 8,
  "checked_at": "2026-09-27",
  "skipped_reason": null
}
```

| 字段 | 说明 |
|---|---|
| `status` | `COLLECTED` 已采集 ／ `SKIPPED` 本次未采集 |
| `paths` | 走的哪条路径（`官方文旅发布` / `搜索引擎索引` / `用户投喂`），供下次按路径复采 |
| `notes_file` | 归一化后的线索卡文件名（`social_notes.py -o` 的产物） |
| `note_count` | 本次提了多少条 |
| `checked_at` | 采集日期 |
| `skipped_reason` | `status=SKIPPED` 时**必填**理由 |

**两种出口都算过，静默跳过不算**：采了就如实写条数与路径；没去采就把理由写出来。
「报『没有』比报假的『有』值钱」——这条规则的判据是**留痕**，不是**必须采到**。

## days：逐日行程（结构化，也是可行性引擎的输入）

数组，一天一项。渲染器生成 `.day` 块，同时这一部分可以直接喂给
`travel_planner.py evaluate` 做确定性检查。

| 字段 | 必填 | 说明 |
|---|---|---|
| `date` | ✅ | `YYYY-MM-DD`。用于生成当日模式映射，**重复即报错** |
| `theme` | ✅ | 当日主题，会进侧栏导航，**要短** |
| `title` | | 日程卡抬头，缺省用 `theme` |
| `summary` | | 今日速览一句话（对应 🧭 那一行） |
| `photos[]` | | `{src, caption}`。**每天至少一张图** |
| `slots[]` | ✅ | `{time, body}` 时段卡，是逐日主体。body 可含 HTML |
| `nearby[]` | | `{name, near, distance, note/brief, evidence}`，沿途顺道点。**每条须核过开放日** |
| `notes[]` | | `{kind, text}`，kind ∈ `summary` / `metro` / `photo` / `stay` / `food` / `warn` |
| `warnings[]` | | 当日踩坑预警，渲染成黄底 warn-line |

### 三条关于数字的硬规矩

`slots[].body` 里出现的**时长与距离**，必须满足其一：

1. 带来源 + 时戳：`全程约 <b>62 分钟</b>（高德路线，查询于 2026-09-27）`
2. 明确标估算：`步行约 15 分钟【估算】`

不许写「大概一小时左右」这种既没来源也没标注的话——`ludbook_check.py` 会逐个抓。

**第三条：决策依赖的数字要挂等级标**（`[A]` / `[B]` / `[C·单源]` / `[D]`）。
它不是装饰——渲染器把它转成小徽章（`.ev`），读者一眼看出哪些能直接依赖。
等级定义与判定见 `evidence-rules.md`：

- `全程约 62 分钟（高德路线，2026-09-27 查）[A]`
- `本地菜馆人均 60（点评 4.6 + 地图在营）[B]`
- `中午人最少[C·单源]`　←　附加说明会渲染成徽章后的小字
- `门票价未核实[D]——请到官方公众号搜「XX景区门票」确认`

> ⚠️ **票价、营业时间、车次时刻、余票、距离车程这几类，不许出现 `[C]`**——
> UGC 给的价格与时间是死线，必须回官方 / 地图 / 铁路核成 `[A]` 或 `[B]`，
> 核不到就老实写 `[D]` 并给出确认方式。这条由 `ludbook_check.py` 第 2 项把关。

## routes：主路线与备选路线（顶层）

用户要的是**能对比**，不是「给一条路走到黑」。一条主线 + **≥2 条备选**：
主线说清怎么走，备选说清**「什么情况走它 + 代价」**两件套。

```json
"routes": {
  "primary": {
    "name": "博物馆 + 老城厢线",
    "summary": "一句话说清这条线怎么走",
    "stops": ["A", "B", "C"],
    "best_for": "什么情况走它"
  },
  "alternatives": [
    {"name": "过江看陆家嘴线", "stops": ["A", "B", "D"],
     "best_for": "想换一边看上海",
     "tradeoff": "中雨天登高只能看雾",
     "brief": "地铁 12 分钟 / ¥3 不换乘，但雨天只看雾 [A]",
     "evidence": "南京东路站 → 陆家嘴站 地铁 12 分钟 / 约 ¥3（高德路线，2026-09-28 查）[A]"}
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `primary.name` | ✅ | 主路线名（渲染成标题） |
| `primary.stops[]` | | 途经站点，按顺序 |
| `primary.best_for` | | 什么情况走它——让读者对号入座 |
| `alternatives[].name` | ✅ | 备选名 |
| `alternatives[].best_for` | | 什么情况走它 |
| `alternatives[].tradeoff` | | **代价 / 前提**。只列地名不写代价，等于把决策又推回给读者 |
| `alternatives[].brief` | | 精简版用的一行说明；缺省时渲染器拿 `best_for + tradeoff + evidence` 拼 |
| `alternatives[].evidence` | | 依据句（含 `[A]` 等标记，渲染器转成徽章） |

**渲染去向**：`primary` → `#drive`，`alternatives` → `#boost`。两者都是**注入既有区块**，
不新开 section——骨架一变，版式指纹与全部示例的逐字节基线会一起失效。
**没有 `routes` 字段时渲染器什么都不做**，本功能对老事实源零影响。

> 对应**交付自查第 28 项**：缺主路线 → 拦；备选 < 2 条 → 拦。

### days[].nearby：沿途顺道可看

主线上**没排进去、但顺路值得进去**的点。每条给「在哪一站附近 + 距离 + 一句说明」。

```json
"nearby": [
  {"name": "人民公园", "near": "上海城市规划展示馆", "distance": "约 116 m",
   "note": "馆就在公园里，等入馆前先逛一圈；全天 05:00-22:00 开、免费 [A]",
   "brief": "全天开、免费 [A]",
   "evidence": "高德 POI，2026-09-28 查 [A]"}
]
```

渲染去向：注入 `#drive`。对应**交付自查第 29 项**（提示级）。

> ⚠️ **每一条都要核过开放日**再写——「顺道去看看」最怕到了门口才发现那天闭馆。
> 采点用 `travel_planner.py nearby-spots`（高德周边搜索），但它返回的常包含
> **景区自身的组成部分**（园内亭台、馆内旧址），筛的时候要认出来。
> 沿线确实没有可顺道的点时，写明原因，别静默略过。

### preferences：个性化偏好（用户自报）

阶段 0 采集到的**用户自报**偏好，用来让主线更贴合本人——饮食、作息、兴趣。

```json
"preferences": {
  "diet": "不吃辣、想吃本帮菜",
  "pace": {"wake_time": "9 点前不起床", "nap": "午饭后要小睡"},
  "interests": ["建筑", "本地菜市场", "避开人挤人的景点"]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `diet` | | 饮食忌口/喜好。字符串或字符串数组 |
| `pace` | | 作息与休息。字符串或 `{wake_time, nap}` 对象 |
| `interests` | | 兴趣标签。字符串或字符串数组 |

渲染去向：注入 `#drive`（主路线区），呈现为「按你的偏好排的（你自报，未做推断）」。
对应**交付自查第 30 项**（提示级）。

> ⚠️ **只呈现用户原话，绝不呈现模型推断**——推断会冒充采集值，违背「每个数字都有来源」。
> 这是软字段（`intake.py` 缺省进 `assumptions`）：没采集不拦，采集了却不呈现才提醒。
> 三键全空时可整个删掉本字段，渲染器对老事实源零影响。

## sections：非行程区块（HTML 片段）

十个区块，**全部必填**，缺一个直接拒绝渲染（`--allow-missing` 不存在，这是故意的）。
用基准骨架的类名写，骨架里每个 section 的注释写清了该填什么结构。

| 键 | 区块 | 该放什么 |
|---|---|---|
| `overview` | 总览 | eyebrow → h1 → `.lead` → `.weather`/`.wday` ×3 → `#prepCard` 出行准备卡（`.check` 清单） |
| `drive` | 路程 | 大交通精确时刻 + 市区交通 + 路程总表 `table.tb` |
| `boost` | 备选 | 时间富余才去的点 |
| `ticket` | 门票 | 票价 / 放票时间 / 预约截止 / 优惠票口径 |
| `tips` | 避雷 | `.tips` 里若干 `.tip`，**内容必须是「真实场景 + 应对」** |
| `stay` | 住宿 | 片区理由 + 已订口径 + 价档参考 |
| `cost` | 预算 | `.stats` 概览 + 逐项表，**必须有隐藏成本行** |
| `sos` | 应急 | `.sos-grid` 里每个关键环节一个 Plan B |
| `eat` | 美食 | 早/午/晚/宵夜 × 地界成表；**每日必须有午餐 + 晚餐行** |
| `gift` | 特产 | 送礼三问 + 推荐 + 「别在景点门口买」提醒 |

### 三个会自动补的结构钩子

渲染器会替你修三处上游踩过的坑，不必自己记：

- `.check` 列表里的 `<li>` 缺 `<input>` → 自动补（缺了会让骨架 JS 抛错、勾选记忆全失效）
- `.tip` 里是裸文本 → 自动包一层 `<div>`（不包会被 44px 序号列挤成竖排，武汉 v1 实物事故）
- 正文里的 `[A]` / `[B]` / `[C·单源]` / `[D]` → 转成 `.ev` 徽章，
  `[C·单源·小红书2026-09帖]` 的附加说明渲染成徽章后的小字。
  **标签属性里和 `<script>` 块里的方括号不动**——钩子只认正文。

但**别指望钩子救内容**：它只补结构，不会替你想「避雷该怎么写」。

第四处不是「补结构」而是「补声明」：`meta.social_intel` 有值时，渲染器会在
`#overview` 顶部注入一条「情报来源」。**注入既有区块而不是新开 section，是为了不动基准骨架**——
骨架一变版式指纹就变，全部示例的逐字节回归基线会跟着失效。

## 用法

```bash
CLI="python <SKILL_ROOT>/tools/travel_planner.py"

# 1. 环境体检（能力先测后报；无高德 key 时相关项须降级 [D]）
$CLI doctor

# 2. 采集校验：必填项缺失就别开工
$CLI validate-request --input 需求.json

# 3. 渲染（--verify 会接着跑版式一致性校验）
python <SKILL_ROOT>/tools/render_html.py 路书_成都.json -o 路书_成都.html --verify

# 4. 内容交付自查（30 项）
python <SKILL_ROOT>/tools/ludbook_check.py 路书_成都.md --days 3

# 5. 行程可行性（排不通就别交付；INFEASIBLE 时退出码 2）
$CLI evaluate --input itinerary_成都.json

# 6. 方案完整性（内连带跑机票/酒店报价校验）
$CLI validate-plan --input final_plan_成都.json

# 7. 对外稿脱敏（要一份规则 JSON，不是直接喂 HTML；结构见 desource.py docstring）
python <SKILL_ROOT>/tools/desource.py desource_成都.json
```

> **从模板复制出来的草稿，第一遍渲染必然报一串 TODO。** 那是模板占位的正常提示——
> 渲染器会把**所有**未替换的占位一次性列出来，不会让你一条条试。

从 `assets/路书事实源模板.json` 复制一份开始改。

## 出错了怎么办

渲染器报错信息都是**可执行的**，不是「失败了」。几个常见例子：

| 报错 | 含义与处置 |
|---|---|
| `基准骨架出现未登记占位符` | 骨架被更新过，新增了 `【…】`。去 `render_html.py` 的 `PLACEHOLDER_MAP` 登记它该填什么 |
| `事实源不合规，共 N 项` | 逐条列出缺哪个 meta、哪个 section 空、哪天的 slots 没写 |
| `以下区块渲染后为空（骨架在、内容缺）` | 你给了片段但它剥掉标签后没内容——上游踩过的坑，光看样式发现不了 |
| `CSS 指纹 ≠ 基准` | 有人手改了 HTML 的 `<style>`。别手改 HTML，回到 JSON 重渲染 |

**改完必须重跑 `--verify`。** 一致性不通过就是没做完。
