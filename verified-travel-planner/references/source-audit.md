# 源核验：标注是声明，核验才是证据

本文件是 `tools/source_audit.py` 的规范说明。只在需要判断「这条徽章标得配不配」
或维护本工具时读它。

---

## 为什么要有这一层

铁律 1 说「每个数字都有来源」，证据四级把来源分成了四档——但**写下 `[A]` 只要一个方括号**。
它声称的事情（有来源、有时戳、可追溯）在 2026-09-27 之前**没有任何机器验证过**。

这和 `freshness.py` 是两个正交的维度：

| 工具 | 问的问题 | 依据 |
|---|---|---|
| `freshness.py` | 这个数字**还新不新**？ | evidence-rules 的 6 类时效阈值 |
| `source_audit.py` | 这个徽章**配不配**？ | evidence-rules 的四级定义 + 死线 |

> 一句话：**时效管「写到哪天为止还作数」，源核验管「标成这个等级合不合规」。**

对标教训：同类项目里 0 个有「引用核验」——引了就算，等读者自己发现。本项目的
护城河是「错了必有钩子拦」，钩子不覆盖标注纪律就等于留了后门。

## 源核验 8 条规则

工具对事实源全文（`days[].slots[].body`、`notes[].text`、`sections.*` 的 full/compact
两档都扫，且**每档各自定位**）机械判定：

| 规则 | 查什么 | 等级 |
|---|---|---|
| **E1 徽章在册** | 全文 A/B/C/D 徽章总数 > 0 | 0 枚 → FAIL |
| **E2 [A] 时戳标注** | 徽章句须有「日期 + 来源词」；只有 slot 级继承算 WARN | 全无 → FAIL |
| **E3 [B] 双源** | 徽章句 ±1 句窗口内 ≥2 个不同来源词 | 0 个 → FAIL，1 个 → WARN |
| **E4 死线** | 门票价/车程距离/开放时段落在 `[C]` 上 | `[C]` → FAIL；`[B]` → WARN（见下） |
| **E5 [D] 出路** | 徽章句 + 下句有「用户可自行确认的方式」或行动出路 | 无 → WARN |
| **E6 source 闭环** | `final_plan.sources` 与 `source_refs` 双向对得上（需 `--plan`） | 悬空 ref → FAIL，孤儿来源 → WARN |
| **E7 同名数字一致** | 同一 POI 两处「高德评分」不同值 → FAIL；「人均」区间无交集 → WARN | — |
| **E8 书写规范** | `[C]` 未带「·单源」标注 | → WARN |

退出码：**0 = 无 FAIL ｜ 2 = 有 FAIL**（与 `evaluate` 一致：排不通不交付）。
WARN 不改退出码——它是「该补课」的清单，不是「不可交付」的判决。

## 判定的四处关键设计（都是实测踩出来的）

### 1. 死线信号归属「最近的徽章」，不是整句

一句里常同时有多个等级：

```
想加一站：兴中广场（高德 4.7）步行 7 分钟 / 0.5 公里[A]，那里 9/24–10/8 办乳鸽文化节（…）[B]。
```

初版把「7 分钟 / 0.5 公里」算到了 `[B]` 头上 → 误报。现在每个价格/距离/时段信号
归给**离它最近的那枚徽章**——`[A]` 已认领的数字不连累同句其他徽章。

### 2. 语境收窄：不是所有「数字」都是死线对象

evidence-rules 的死线清单是**门票价格 / 营业时间 / 车次时刻 / 余票 / 距离车程**——
不是「一切价格」和「一切分钟数」。初版宽正则的实测误报：

- 「人均约 ¥40–60（攻略口碑）[C]」——餐费预算，不在死线清单
- 「每 5–15 分钟一班[C]」——班次密度，不是换乘时长（单独归入 WARN）
- 「12 公里环湖绿道[B]」——景观长度，不是换乘距离（`绿道|环湖|海岸线|栈道` 前缀豁免）
- 「多云 27–33℃」整段——表格拼接后被裸「车程」二字误伤（`</td>` 已当句界）

**误报比漏报更伤**：一个满屏假警报的闸门，人第二次就不看了。

### 3. `[B]` 死线的分档：规范内部有张力，如实呈现

- `evidence-rules.md` 的死线明文只禁 `[C]`：「C 级信息**绝不能**用于……」
- `SKILL.md` 更严：这几类「**只能取 `[A]`**」

两者相撞时工具不装作没看见，也不擅自裁决：**`[C]` 判 FAIL，`[B]` 判 WARN**
（第三方聚合双源是次优解，点名叫人建议官方渠道复核）。这条张力留给规范作者决定，
工具只保证「两种口径下都点得出来」。

### 4. 双档各报各的，且定位符带档位

`slots[].body` 可写 `{"full": …, "compact": …}` 双档（`sections.*` 天然分档）。
第一版把两档**合并成一个逻辑槽位**去审，输出是灾难性的：

```
[D1 09:45] 时戳/来源靠 slot 内继承，徽章句自身没带
    …公交同一段是 43 分钟[A]，拖行李不划算，直接打车。
[D1 09:45] 时戳/来源靠 slot 内继承，徽章句自身没带
    …公交同一段 43 分钟[A]，拖行李不划算，直接打车。
```

**同一个定位符、正文只差一个「是」字** —— 读者没法判断这是「同一处报了两遍」
还是「两处都有问题」。实测中山一轮报出 29 条 WARN，**近半数是这样成对的**
（E2 / E3 / E4 各有若干对）。噪声会把整张清单的信用耗掉，
**而「噪声大的闸门一定会被绕过」是本项目的既有教训**。

改法：`slot_texts()` 把双档展开成两条，定位符加档位后缀（`D1 09:45·精简版`）。
顺带修正了 E2 的口径 —— slot 级继承从「跨档继承」改成**档内继承**：
精简版读者只看得见 compact 档，拿完整版的时戳去「继承」等于替他补了一个他看不到的来源。
单档（字符串 body）不加后缀，既有输出与基线一字不变。

## 示例的定位（重要）

| 示例 | 源核验结果 | 定位 |
|---|---|---|
| 中山 | **FAIL 0**（29 条 WARN 为补课清单） | 证据纪律基线：源核验 8 条规则、140 枚徽章（含双档）的完整覆盖 |
| 成都 | **E1 FAIL**（0 徽章） | 产出于 evidence-rules 之前；是**版式回归基线**（逐字节 MD5 重现），**不是证据纪律基线** |

成都这份**不要为了「全绿」补徽章**——它的价值是「同一份事实源渲染逐字节可重现」，
补标徽章会改渲染输出、破坏那条回归基线，且我手上没有 9 月做成都时的查询上下文，
补出来的等级是**编造的证据等级**——那正是本 skill 最不能接受的行为。

新产出的路书（中山规范起）必须过 `source_audit`；成都按 legacy 处理，
跑 CI 时对它豁免 E1，其余规则对它恒 PASS（无徽章可违）。

## 这次源核验抓到了什么（首次跑真实产物的结果）

2026-09-27 首次对中山示例运行，**5 条 FAIL 全是真缺陷**，均已修复：

| 缺陷 | 违反 | 修复方式 |
|---|---|---|
| 影视城门票 ¥39.9 标 `[C·单源]` | E4 死线 | 并入多渠道价格带 `[B]`（携程/马蜂窝/永安），并补 `[D]`「以官方渠道当日价为准」 |
| 詹园线上票 ¥49.9 标 `[C·单源]` | E4 死线 | 官方现场价保留 `[A]`，线上价降 `[D]`「下单前以携程当日页为准」 |
| 预算表「故居免费」标 `[C]` | E4 死线 | 降 `[D·官方渠道可核]` |
| 送礼段 `[A]` 无查询时戳 | E2 | 补「查询于 2026-09-27」 |
| `weather-zs` 从未被 plan 引用 | E6 孤儿 | 挂到 `d2_sunset`（日落活动受天气影响） |

**共同模式**：这 5 处都不是「写错数字」，是**把单源信息标成了它够不着的等级 / 漏了
可追溯要素**。数字本身当时都查过、都对——这正是「标注纪律」与「事实正确」的区别。

## 局限与下一步（不做的事）

- **本工具审计「标注纪律」，不重查「内容真实」**。这一层已建成**三层链**
  （2026-10-01）：
  ① **声明↔留痕比对（`tools/claim_audit.py`，v2）**：高德采集默认留痕
  （快照内嵌 `raw_calls`；`search-places`/`nearby-spots` 可 `--trace` 落盘），
  实采段时长与段车费必须如实进路书，丢失/被改即 FAIL；
  ② **来源回声核查（`tools/echo_audit.py`）**：抓取线索卡引用页正文，验证
  声称的数字/时刻/关键短语真的在页面上，死线类对不上即 FAIL；
  ③ **独立源核查（`tools/cross_check.py`）**：各来源页面正文重合比对，
  拆穿「互相转载充双源」。三层的设计与边界见 `references/echo-cross.md`。
  **仍未跨越的**：留痕/回声证明「声明与采集与页面一致」，不证明「页面说的对」；
  语义等价改写、JS 渲染页、引用页自身的内容错误，机器都兜不住。
- 不做「自动改徽章」：改等级是判断，判断必须留给人（和 skill 的写作规则）。
- 来源词表（`SOURCE_WORDS`）是识别能力的短板：漏一个「文旅」就会把有来源的 `[B]`
  误判成无来源（实测踩过）。与 `freshness.py` 的词表须**两头同步**。
