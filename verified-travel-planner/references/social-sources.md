# 社媒采集渠道：能力矩阵、扩展路径与合规边界

阶段 3.5 的**渠道层**文档。回答三件事：

1. 现在能从哪些渠道拿到社媒内容？（能力矩阵）
2. 想拿更多，往哪个方向扩？（五条扩展路径）
3. 每条路上，合规 / 反爬 / 内容解析各要注意什么？

> 机器可查版：`python tools/social_source.py --doctor`
> 采集计划版：`python tools/social_source.py --plan <目的地> --days 3 --month 9月`
> **用户授权登录（能不能用你的账号读）** → 单独一页：`references/social-login.md`

---

## 一、先说结论：当前的集成方式是什么

**本包与小红书、抖音之间没有任何直连。** 这不是没做，是实测做不了：

| 目标 | 本机实测结果（2026-09-27，无头 Edge 匿名） |
|---|---|
| 小红书 首页 / 搜索页 / 笔记详情页 | **全部**返 `安全限制 · IP存在风险 · 300012` |
| 抖音 搜索页 | `验证码中间页` |

**两者都是风控拦截，不是登录墙。** 这个区分很关键——如果是登录墙，
「登录一下就能读」成立；是风控，则登录也未必读得到，而「想办法绕过去」
会直接撞上铁律 8（遇风控一次即停手，不重试、不换 UA、不打验证码接口）。

所以本包的社媒能力**建立在「间接渠道」上**，走三条路：
**官方文旅发布**（可到 `[B]`）→ **搜索引擎索引**（`[C·单源]`）→ **用户投喂**（`[C·单源]`）。

> 一句话：**不是从平台里捞，是从平台的公开投影里捞。**
> 投影（官方转载、搜索引擎索引、媒体图文、攻略站）覆盖面窄一些，但稳定、
> 可溯源、可复核，且完全不碰风控与合规红线。

**那「我登录一下」能不能读？** 能，但**它换不来更高的证据等级**——
登录只提升覆盖度，UGC 天花板照旧 `[C·单源]`，而账号风险由你承担。
本轮把这条路做成了一个独立通道（**AUTH 档**），完整判断与操作步骤见
`references/social-login.md`；这里只登记它的三条实现方式与风险。

## 二、能力矩阵（五档 · 21 条渠道）

状态含义：
`READY` 本机零配置可用 ｜ `UNCONFIGURED` 需一次配置 ｜ `BLOCKED` 实测不可达，已放弃

**「证据上限」是渠道决定的硬天花板**，内容再好也越不过去（判据见 `evidence-rules.md`）。
每一行的「实证」列都是**本机真跑过一次的记录**，不是查文档得来的。

### OPEN · 零配置，本机实测可用

| id | 渠道 | 上限 | 产出 | 主要局限 |
|---|---|---|---|---|
| `gov_official` | 官方文旅门户 + 权威媒体转载 | **B** | 2–6 条/目的地 | 只给「线路组合 + 玩法定性」，不给体验细节 |
| `wechat_mp` | 微信公众号图文（文旅局/地方媒体） | **B** | 1–4 条/目的地 | 反盗链，只能读文字；模板段多 |
| `ota_guide` | OTA 攻略站（携程 / 同程） | C | 3–8 条/目的地 | 动线常是「一天打包」；**URL 必须来自搜索索引，不可自己拼** |

**本机实证（2026-09-27，无头 Edge，每站只试一次）**

| 渠道 | 实测结果 |
|---|---|
| `wechat_mp` | `mp.weixin.qq.com/s/…` 取 DOM 得 **4.7 MB / 正文块 22 个**，命中官方发布原文《双节来中山怎么玩？十大热门景区、八条精品旅游线路公布》 |
| `weibo_search` | 搜索页取 DOM 得 93 KB / **内容块 147 个**，无风控标记 |
| `bili_search` | 搜索页取 DOM 得 1.1 MB / **42 张卡片**，无风控；字段完整率 **42/42**（标题 / UP主 / 播放量 / 链接，时长 39/42）。详情页可读标题、UP主与**完整简介** |
| `gov_official` | `zs.gov.cn/wglj`（中山市文旅局）官网可完整读取，含**《中山A级旅游景区名录》**与**《2026年度诚信店名单（32 家文旅经营单位）》** |
| `ota_guide` | 手拼的 `you.ctrip.com/place/zhongshan1215.html` 实际返回**「沃斯」攻略页**——正是 `geomatch` 警告的那类地理错配 |

> ⚠️ **B站被误判过两次**。第一次：把页面里的「**登录**」按钮文案当成了登录墙；
> 第二次（2026-09-27 复测详情页）：搜到 `-352` 就当成风控码——实际那是 CSS 里
> `background-position:-3520px` 的子串。
> 判风控要看**返回体特征**（状态页、错误 JSON、WAF 脚本），不是 grep 关键词。
> 这条已写进 `--doctor` 的实现注释。

**B站字段边界（2026-09-27 实测，42 张卡片）**

| 层 | 拿得到 | 拿不到 |
|---|---|---|
| 搜索页 | 标题 42/42 ｜ UP主 42/42 ｜ 播放量 42/42 ｜ 链接 42/42 ｜ 时长 39/42 | **简介**（搜索页根本没这个字段） |
| 详情页 | 标题、UP主、**完整简介**、**评论区正文** | 点赞数；口播内容 |
| 评论区 | 用户名 / 时间 / **正文**（正反评价都有） | 未登录只渲染 3/6 条，全量需 AUTH 档 |

> **评论文怎么拿**：`tools/cdp_read.py <url> --scroll 40`。
> 评论区是**懒加载 + 嵌套 45 层 Shadow DOM**，`--dump-dom` 拿不到——**但那不是风控**。
> 完整方法与红线见 `references/transcript-and-comments.md`。

**所以 B站的定位是「话题发现 + 热度排序」**（标题与播放量足以排序），
**不是「取事实」**——视频里真正说的内容（口播）一个字都拿不到，`[C·单源]` 天花板不变。
另：关键词会混入无关内容（实测搜「中山饮食」混进**房价曝光**与**增肥 vlog**），
拿到后必须按关键词二次过滤，不能直接当目的地线索用。

### AUTH · 需用户授权登录（**风险落在你的账号上**）

> **总纲：登录只提升覆盖度，不提升证据等级。** UGC 天花板照旧 `[C·单源]`。
> 强度递增、风险递增：人工辅助 < 半自动读取 < 批量采集。
> 完整说明与操作步骤 → `references/social-login.md`

| id | 渠道 | 上限 | 关键判断 |
|---|---|---|---|
| `logged_in_cdp` | CDP 接管已登录浏览器（人工导航 + 自动读取**一页**） | C | **本轮落地的那条**。独立 profile 扫码一次 → headless 复用。**不做批量、不做并发**——一旦自动化，风险从「平台条款」升级到「你的账号被限」 |
| `local_crawler` | 本地采集工具（MediaCrawler 类，扫码 + 批量翻页） | C | **许可证多为非商业**（MediaCrawler 用 NON-COMMERCIAL LEARNING LICENSE）；走**签名对抗**路线，与铁律 8 对冲。**不默认启用** |
| `third_party_api` | 第三方社媒数据 API（TikHub 类，按次付费） | C | 第三方聚合**上不到 `[A]`**；按次计费（约 $0.001–0.01/次），调试时同参数重拉容易烧额度 |

### GATED · 需资质或付费，当前未配置

|---|---|---|---|

## 二·补、这轮实测改变了什么

原来的三条路径是「**因为直连不可行，所以只能间接取**」。补测之后结论更细：

| 原来的判断 | 实测后的修正 |
|---|---|
| 小红书 / 抖音 = 不可读 | 成立，且**同类的知乎 / 马蜂窝也不可读**——不是个别站点，是**国内 UGC 平台的整体姿态** |
| 只能靠搜索引擎的**转述** | **错**：`wechat_mp` 能读到**原文**（4.7 MB 全文 DOM），官方发布这条路径的信息量被低估了 |
| 国内社媒没有可读的 | **错**：**微博**与**B站**的搜索页零配置可读——它们补上了「实时热点」和「话题发现」这两块原来完全空白的拼图 |
| 官方渠道只有榜单 | **错**：官方门户还发布**名录类**内容（A 级景区名录、诚信店名单）——**这是唯一有官方背书的「店单」来源**，对吃/店选择的价值高于任何 UGC |
| 登录一下就能读小红书 | **半对**：通路已实测可用（CDP + 独立 profile），但**登录换不来更高等级**，且**登录态下能否读到仍未验证**（需你亲自扫码）。详见 `social-login.md` |

**结论**：社媒情报的可用面比原先宽，但**结构没变**——
能读的多是「官方 / 公开索引 / 中长文本平台」，读不到的是「强互动、强个人信息、强风控的短内容平台」。
后者的内容**只占体验类信息的一部分**，而且恰恰是最容易失真的一部分。

## 二·补二、用户授权登录（AUTH 档）的三条实测

完整版见 `references/social-login.md`，这里留三条最关键的：

| # | 实测 | 对设计的影响 |
|---|---|---|
| 1 | **Edge 对 Cookies 持独占锁**（复制报 `err=32`），同 `--user-data-dir` 起第二实例直接失败 | 所以「复用你日常浏览器的登录态」**做不到**；只能用**独立 profile 登录一次再复用** |
| 2 | 独立 profile + CDP **通路可用**（Edge 154 / CDP Protocol 1.3），读一页 B站搜索页得 **1.1 MB DOM / 5557 字符正文**，Cookies 正常落下 | 「半自动读取」这条**技术上成立**，工具已落地（`tools/social_login.py`） |
| 3 | 匿名读小红书 = 标题「安全限制」、抖音 = 「验证码中间页」，探针均 `exit 2` | **风控判据是响的**（正负向都验过）；同时说明**登录前这条路产出为 0** |

> ⚠️ **踩到的坑：「有 cookie」≠「已登录」。**
> 第一版诊断报「已登录：B站、小红书、抖音」——是假的。匿名访问同样会下发设备/风控 cookie。
> 修法：判登录态看**标志性 cookie 名**（`web_session` / `SESSDATA` / `sessionid` / `SUB` / `z_c0`），
> 不看「有没有 cookie」。**判据要落在「是不是」，不是「有没有」。**

## 三、五条扩展路径（按性价比排序）

### 路径 1 · 把官方渠道吃干榨尽（零成本，**优先做这个**）

现在 `gov_official` 的产出只有 2–6 条/目的地，**远没有吃满**。可做的：

- **多级官方源**：文旅局（市级）→ 文旅厅（省级）→ 政府新闻发布厅 → 地方党媒（日报/晚报客户端）
- **多类发布物**：精品线路榜单、节庆档期、消费券活动、新开放景区公告、交通接驳公告
- **名录类（本轮新发现，最值钱）**：官网的**统计/公开栏目**里有
  「A 级旅游景区名录」「**诚信店名单**」「公共文化设施一览表」这类**经官方核定的清单**。
  这是**唯一有官方背书的「店单」来源**——比任何 UGC 榜单都硬，而它一直在那儿没人看。
  > 中山实测：`zs.gov.cn/wglj` → 公告公示 / 统计数据 两栏，拿到
  > 《中山A级旅游景区名录》与《2026年度中山市诚信店名单（32 家文旅经营单位）》。
- **时间轴展开**：把「目的地 + 月份」放进关键词，档期类信息命中率高
  > 已验证的有效问法：`<城市> 文旅局 发布 精品线路 十大景区`、
  > `<城市> <月份> 文旅活动 精品线路`（全套问法由 `social_source.py --plan` 直接生成）
- **读原文而不是转述**：公众号图文可整篇读（实测 4.7 MB DOM），
  **别停在搜索引擎摘要那一步**——摘要会丢档期精确日期与主会场

> 中山实战验证：正是这条路坐实了「南洋风情旅游周 9/27–10/8，主会场孙文西路」——
> 而那是行程里价值最高的一条线索（零交通成本、正好落在档期里），
> 也是**唯一能到 `[B]` 的社媒情报**。

### 路径 2 · 加配一个抓取代理（一次配置，提升「抓得到」的比例）

适用场景：目标页要求 JS 渲染、有反盗链、或本机 IP 被限流。

- 可选：**抓取类连接器**（`deepseek`/Tavily/Exa/Firecrawl 系聚合）、**云采集 SaaS**
- 关键认知：**代理解决的是「可达性」，不解决「可信度」**。等级天花板照旧 `[C]`
- 成本模型：多按调用计费 → **先跑「官方」与「档期」两类关键词**（命中率最高），再跑长尾

### 路径 3 · 用你自己的登录态（AUTH 档，**要你拍板**）

前三类都不碰账号；这一条碰。它只在**官方与索引路径确实拿不到、而那部分内容又对你重要**时才值得。

- 最轻：**用户投喂**（见路径 4）——你刷到就贴过来，零风险
- 中间：`logged_in_cdp` + `tools/social_login.py`——你扫码一次，之后它只读**单页**，不批量
- 最重：`local_crawler`（MediaCrawler 类）——**能拿几百条，但有非商业许可 + 账号风险，默认不启用**

**判断这件事只需要问一句**：这条线索只能靠登录才拿得到吗？
如果是，那它在证据体系里的分量本来就低（仍 `[C·单源]`），
**用账号风险去换它，多半不划算**。完整权衡见 `social-login.md` 第一节的表。

### 路径 4 · 用户投喂常态化（零成本，提升「深度」）

真实用户能打开采集端打不开的页面。把投喂**做成默认动作**：

- 阶段 0 需求采集时顺带问一句「有没有刷到过相关的笔记/视频？发链接给我」
- 收到截图 → 人工转录后**必须标 `manual_transcript`**（转录即可能失真）
- 线索卡里记**平台 + 账号 ID**（只记名字会认错号，见 `sources.md`）

### 路径 5 · 开放平台接口（有资质才做，唯一能上 `[A]`）

只有在**需要长期、批量、稳定**地取数，且**主体资质能过审**时才值得投入。
个人出行场景下，性价比低于路径 1–3——**别为了等级好看去申请一个用不上的应用**。

## 四、三条注意事项（每一条都有对应的失败模式）

### 4.1 合规性

| 事项 | 具体做法 | 越线表现 |
|---|---|---|
| 只读公开内容 | 不登录、不点赞、不关注、不评论、不私信 | 用采集账号做任何互动 |
| 不绕风控 | 遇拦截一次即停手（铁律 8） | 换 UA / 换 IP / 打验证码接口 / 猜接口签名 |
| 不采个人信息 | 昵称与公开账号 ID 可记；**联系方式、住址、行程轨迹不可** | 把笔记里的微信号、手机号落进线索卡 |
| 著作权 | 摘录事实性信息 + 署名 + 出处链接；不整篇转载 | 把攻略正文复制进路书 |
| 平台条款 | 遵守 robots 与站点 ToS；商用场景额外确认 | 用「代理池」批量抓一个明确禁止的站点 |
| 本包边界 | **只读**——不购买、不预订、不支付、不候补、不输验证码 | — |

> **一句提醒**：`crawler_saas` / `local_crawler` / `third_party_api` 这几条路，
> **合规责任在使用者**，不在工具。工具只负责把「这条路的边界在哪」写清楚。

### 4.2 反爬限制

- **风控 ≠ 登录墙**：识别方法——看返回是「风险提示/验证码页」还是「请登录」。
  前者别试，后者也只是提示，不代表登录后就能批量读。
- **失败即降级，不重试**：一次拦截就换渠道（`--plan` 只列 `READY` 渠道就是这个设计）。
- **节奏比速度重要**：真要批量，请求间隔放宽到 1.5s 以上、失败退避 3s×3 次
  （这是本项目调高德接口验证过的节奏，见 `experience.md`）。
- **别拿账号冒险**：`local_crawler` 与 `logged_in_cdp` 的最大风险不是抓不到，
  **是用户自己的账号被限**。所以前者不默认启用，后者只读单页、不翻页不并发。

### 4.3 内容解析

- **索引摘要不是正文**：线索卡的 `url` 必须落在**原页**，摘要一律不写进去。
- **同源转载要识别**：一篇内容被十家媒体转载，仍是**一个来源**。
  识别信号：正文段落逐字相同、发布时间密集、无独立采访信息。
- **互动指标只当热度信号**：赞藏评高 ≠ 内容对**你**有用，更 ≠ 事实正确。
- **时效**：`checked_at` 必填；档期类线索过了结束日期就自动 `stale`（见 `social_notes.py --merge`）。
- **抽取后必过死线过滤器**：票价 / 营业时间 / 车次余票 / 距离车程
  —— 这四个字段在解析阶段就该被拦掉，不要让它们流到路线层才被发现。

## 五、把「扩渠道」变成流程的一部分

`tools/social_source.py` 的两个动作已经嵌进工作流：

| 时机 | 动作 | 目的 |
|---|---|---|
| 阶段 1 能力自检 | `social_source.py --doctor` | 开工前就知道这趟能走哪几条路、天花板多高 |
| 阶段 3.5 采集 | `social_source.py --plan <目的地>` | 生成关键词组与渠道顺序，不用每次现想 |
| 阶段 3.5 采集（AUTH 档） | `social_login.py --check / --launch / --grab` | 用户授权登录后的单页只读读取 |
| 阶段 5 交付自查 | `ludbook_check.py` 第 ㉗ 项 | 采集了必须声明，没采集必须写理由 |

**扩展渠道的正确姿势**：在 `social_source.py` 的 `PROVIDERS` 里加一条，
把它的 `tier` / `ceiling` / `limit` / `compliance` / `parse` 一并写清楚——
**只登记「能力」，不登记「愿望」**。写不进 `ceiling` 的渠道，等于还没定义好。
