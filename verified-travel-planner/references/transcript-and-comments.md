# 口播文案与评论区：怎么拿、拿得到什么、哪里是红线

> 2026-09-27 实测。这两条路的**难度和性质完全不同**——
> 评论是「把页面滚起来就能读」，口播是「要么平台给了字幕，要么就越线」。

## 一、结论速览

| 目标 | 能不能拿 | 靠什么 | 证据上限 |
|---|---|---|---|
| **评论区正文** | ✅ **能**（未登录即可读到部分） | `tools/cdp_read.py` + 滚动触发懒加载 + Shadow DOM 穿透 | `[C·单源]` |
| **平台字幕** | ⚠️ **取决于 UP 主传没传** | 只读页面，字幕面板 DOM | `[C·单源]` |
| **口播音频 → 本地转写** | ❌ **本项目不做** | 技术上可达，但越线（见第五节） | — |
| **用户投喂的转述/截图** | ✅ 能，且最合规 | 阶段 0 顺口问一句 | `[C·单源]` |

## 二、评论区：已经工具化了

### 为什么原来的 `--grab` 拿不到

`--dump-dom` 只取**首屏静态 DOM**，于是：

1. **评论区是懒加载的**——不滚动就不请求，DOM 里只有一个空壳 `bili-comments`；
2. **评论区在 Shadow DOM 里**，且**嵌套 45 层**（实测），普通选择器一律穿不进去。

**这两条都不是风控**。实测同一视频：`--dump-dom` 得评论 0 条；CDP 驱动滚动后，
拿到 6 条评论的计数与其中 3 条的正文。

### 操作步骤

```bash
# 读一页（--scroll 触发懒加载，数字按页面长度给）
python "<SKILL_ROOT>/tools/cdp_read.py" "https://www.bilibili.com/video/BVxxxx/" --scroll 40

# 只关心评论相关文本
python "<SKILL_ROOT>/tools/cdp_read.py" "<url>" --scroll 40 --grep 回复

# 落盘完整结果，供后续归一化
python "<SKILL_ROOT>/tools/cdp_read.py" "<url>" --scroll 40 --out 原始DOM.json
```

`cdp_read.py` 是**零第三方依赖**的——内置了一个最小 WebSocket 客户端（RFC 6455），
因为本机 Python 没有 `websocket` / `websockets` / `requests`。

### 实测拿到了什么（2026-09-27，B站，未登录）

```
我想养只黑猫Alex        我觉得煲煲掂的乳鸽就很好吃了          3小时前
识探GOODTASTE          中等偏上吧                          3小时前
恶魔之子001            以前吃蛤蟆时就去，自从改左做吃鸽就去过一次，真系唔觉好吃   2小时前
```

**注意第三行**：粤语差评，且带着具体经历。**这正是口碑层要的东西**——
而且同一批评论里正反两面都有，天然构成对照。

### 未登录状态的限制（实测）

- 页面提示「**登录后查看 6 条评论**」与「请先**登录**后发表评论」
- 实际渲染出 **3 条**（计数 6 条），其余需登录或继续交互才加载
- **读得到正文，发不了言**——后者正是我们不需要的

**结论**：未登录能拿到**部分**评论，够做定性判断；要拿全量须走 AUTH 档
（`social_login.py` 独立 profile 扫码，**风险落在用户账号上**）。

## 三、口播文案：先看平台有没有给字幕

### 路径 A · 平台字幕（首选，纯只读）

B站播放器有字幕面板（`bili-subtitle-x-subtitle-panel`），字幕由 **UP 主上传**。
有字幕时，它就在页面 DOM 里，`cdp_read.py` 直接读得到。

**实测（2026-09-27，那条中山乳鸽视频）：字幕接口返回空 → 这条视频没有字幕。**
面板存在但 `display: none`。所以**字幕是「有则白拿，无则没有」**，不能指望。

判断办法：读页面时看有没有 `bili-subtitle-x-subtitle-panel` 且内容非空。

### 路径 B · 音频转写（**本项目不做**，见第五节）

技术上：CDP 的 Network 事件能观察到页面**自己**请求的音频流
（实测抓到 `…-1-30216.m4s`，即 B站音频流）。但**用它下载音频就是越线**，理由在第五节。

### 路径 C · 用户投喂（最合规，推荐）

**用户自己看视频**，把要点转述或截屏给项目：

- 用户可以用**站内自带的 AI 视频总结**先看一遍要点（这是平台功能，用户自己用，完全合规）
- 项目只接收结论，标 `[C·单源]`，记平台与账号 ID
- 截图须标 `manual_transcript`（人工转录，可能失真）

**这是「用户授权」最轻的一档，零账号风险。** 阶段 0 采集需求时就顺口问一句。

## 四、这些数据进来之后怎么用

无论评论还是口播转述，**一律 `[C·单源]`**，且照旧受四条死线约束：

| 可以（`[C]` 允许的用途） | 绝对禁止（死线） |
|---|---|
| 玩法与体验描述 | 门票价格 |
| 人流 / 排队的体感 | 营业时间 / 开放状态 |
| 季节时机 | 车次 / 航班时刻 |
| 路线顺序建议 | 距离 / 车程 |

评论里写的「9 点开门」「门票 80」**照样拒**——`social_notes.py` 会把这类判为死线违规。

**评论进线索卡的方式**：挂在该条 note 的 `reviews[]` 下，`stance`（支持/反对/中立）
由**人**登记，机器不判语义；机器只做**水军信号**（空洞 / 雷同 / 批量昵称）与**夸大信号**，
一律**只出信号不出结论**，每条带免责声明。详见 `social-credibility.md`。

## 五、红线：什么不做，为什么

| 不做 | 为什么 |
|---|---|
| **下载音视频做转写** | ① 视频页明确标「未经作者授权，禁止转载」；② 越过了本包「不下载视频」的边界；③ 转写产物会进路书，等于二次分发版权内容 |
| **猜接口签名（WBI 等）** | 平台加签名的目的就是限制自动化访问，复现它属于 `social-sources.md` 列明的**越线表现**（「猜接口签名」） |
| **批量翻页 / 并发采集** | 风险从「违反平台条款」升级到「**用户账号被限**」——而代价只换来 `[C]` 级线索 |
| **换 UA / 换 IP / 打验证码接口** | 铁律 8：遇风控**一次即停手**，不重试、不绕 |
| **采个人信息** | 昵称与公开账号 ID 可记；**联系方式、住址、行程轨迹不可** |

**总纲**：**登录只提升覆盖度，不提升证据等级。**
UGC 的天花板照旧 `[C·单源]`——**用账号风险去换 `[C]` 级线索，多半不划算。**

## 六、判风控看返回体，别看关键词

**同一条铁律已经栽过两次**（记在 `experience.md` 第 12 条）：

1. B站搜索页把页头的「**登录**」按钮文案当成了登录墙——实际 DOM 1.1 MB 完全可读；
2. B站详情页把 CSS 里的 `background-position:-3520px` 当成了风控码 `-352`。

`cdp_read.py` 的判据是**返回体特征**：

| 特征 | 对应 |
|---|---|
| `IP存在风险` / `300012` | 小红书 |
| `验证码中间页` | 抖音 |
| `暂时限制本次访问` | 知乎（接口级） |
| `submitWafFeedback` | 站点级 WAF |

**页面里出现「登录」两个字，不等于登录墙。**

## 七、能力边界（诚实清单）

**能做**

- 读公开页渲染后的正文，含多层 Shadow DOM
- 滚动触发懒加载（评论区、动态加载的内容）
- 判风控（按返回体特征）

**做不到 / 不做**

- **滚动到底再截图**：`Page.captureScreenshot` 未启用；要长图得另开
- **精确 <496px 视口截图**：Edge 无头模式有最小视口陷阱，见 `browser-use.md`
- **下载音视频**：不做（第五节）
- **读需要登录才渲染的完整评论区**：须 AUTH 档，风险在用户账号
- **视频口播内容**：除非 UP 主传了字幕，否则本项目拿不到——**这一层只能靠用户投喂**
