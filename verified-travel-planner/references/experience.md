# 经验沉淀

**这套 skill 值钱的不是规矩，是规矩后面的翻车实录。**

每次行程结束后往这里追加。写清三件事：**撞了什么坑 → 现在立的什么规矩 → 怎么验的**。

下次触发本 skill 时先读这里。

## 已固化的教训（来自两个开源标杆的实战积累）

以下每一条都是真实撞过的坑，本 skill 的规矩就是从它们来的。

### 关于数字溯源

- **车程是编的**——曾经的攻略里"30 分钟车程"是模型估的，实际开了 50 分钟。
  → 立规矩：所有交通时长必须来自地图调用，带时戳。
- **票价是旧的**——沿用了一个月前的门票价，实际已涨。
  → 立规矩：检索时点 = 当下，不许沿用会话早前结果或记忆价。
- **联票重复计价**——联票 90 已含景交，又另算了景交 20×4，预算虚高 50 元。
  → 立规矩：多档价格先拆清结构再算账，逐档核对官方商品名。

### 关于交付质量

- **5 天行程没有一天凑齐三顿饭**——早餐两天空缺、宵夜无。
  → 立规矩：餐行机械钩，逐日 grep 报数，每日必须早/午/晚三行。
- **已取消的行程还挂在别处**——改了一处忘了另一处，错误反复复活。
  → 立规矩：同一决策点全文同步，判据 = 旧值在"活条款"里归零。
- **成品改了十几轮，底稿一字没动**——从旧底稿重建 = 旧错误必然重演。
  → 立规矩：双写制，事实源 JSON 与 HTML 成稿必须当批同步。
- **避雷 12 条转成分发版只剩 8 条**——降维丢失。
  → 立规矩：分发产物必须能从事实源重新生成，转换时与源逐条对照。
- **对外稿混进不该有的字眼**——脱敏没归零。
  → 立规矩：脱敏归零，grep 必须为 0，报数必出。

### 关于配图与视觉

- **拿古画冒充地标**（黄鹤楼 = 绢本古画）——挑图没建概念就搜。
  → 立规矩：挑图先写下地标真实外观特征，再核对拍摄对象与年份。
- **在建期照片当地标**（大桥 = 塔吊未合龙）——同一坑。
- **重滤镜无标志物**（湖泊 = 渔船剪影认不出）——同一坑。
  → 立规矩：三类直接跳过——古画/版画、在建照、重滤镜无标志物。
- **裸 opacity:0 依赖 IntersectionObserver**——JS 挂掉，83% 内容不可见。
  → 立规矩：动效必须 html.js 门控 + 兜底脚本，JS 禁用/启用两态实测。

### 关于能力判断

- **还没试就断定小红书要登录**（确实是，但是猜中的）——同样的猜法用在携程上就错了（携程机票根本不用登录）。
  → 立规矩：试一次再报，没试就说"没试过"，不说"不行"。
- **把笔记图片当成读不了，从没截图**——实际完全可读，且图片里才有明细账单。
  → 立规矩：读图，不只读文字。
- **报告某功能没做，其实代码就躺在文件里**——因为从没运行过。
  → 立规矩：跑了再说。
- **高德对境外返回同名国内地点**（查"东京"得广西一个村庄），坐标格式完全正常。
  → 立规矩：境外必须识别并拒绝这类结果。
- **把酒店订房页当成机票页**（同域名不同登录态）——一个页面证明不了另一个。
  → 立规矩：每个动态源单独判断登录态。
- **"同一目标连跑 4 版脚本"**——止损点没设。
  → 立规矩：同一信息最多搜 2 轮，遇验证码一次即停手换路径。

### 关于文案

- **"破折号滥用 / 粗体堆砌 / 三段式排比 / 通用积极结尾"**——grep 抓不到的结构性问题。
  → 立规矩：去 AI 味双通道，grep 高频词 + 通读结构。
- **称谓不统一**——一个称呼改三遍不统一。
  → 立规矩：拍死口径，旧称即违规。

### 2026-09-27 中山（3 天 2 晚 · 闺蜜局 · 珠海出发）

**这是本 skill 第一次跑真实行程**（此前全部是自测）。当时四道闸门最终全绿
（现为六道，后加时效体检与源核验/精简版核验），但过程踩了 7 个坑，全部记下。

- **坑：事实源 JSON 里混进英文双引号**，渲染器直接 `FATAL 事实源不是合法 JSON：Expecting ',' delimiter`。
  → **立规矩**：事实源正文里的中文引号一律用「」，绝不写英文直引号。
  → **怎么验的**：进渲染器之前先 `json.loads()` 验一次合法性。

- **坑：`validate-plan` 报 8 个景点 `has no reason to visit`，但 `why_visit` 明明写了内容**。
  真实原因是引擎的 `_strings()` 只吃**数组**，收到字符串直接判空——报错信息完全没提这点。
  → **立规矩**：`features` / `why_visit` / `source_refs` 三个字段必须是数组，单项也要包一层。
  → **怎么验的**：报错逐条列出 attraction id；改成数组后复跑得 `VALID`、0 错误。

- **坑：`evaluate` 报 `DAILY_DURATION_EXCEEDED`——单日跨度硬上限是 720 分钟（12 小时）**。
  旅游日 12 小时本是常态，但引擎按硬阈值报警。
  → **立规矩**：排程时把首尾活动压进 12 小时内，否则只能带着 WARNING 交付。
  → **怎么验的**：D1 末段收到 21:00、D2 早段推到 08:30，复跑得 `FEASIBLE / score 100`。

- **坑：高德报 `CUQPS_HAS_EXCEEDED_THE_LIMIT (10021)`，一度误判成日配额用光**。
  实际是**并发/QPS 限制**，跟日配额无关。
  → **立规矩**：连续调 `search-places` / `route` 时每次 `sleep 1.5`，失败 `sleep 3` 重试 3 次。
  → **怎么验的**：同样 14 段路线，裸连挂掉 8 段；加延时后 14 段全成。
  → **2026-09-28 已入代码（本条规矩作废一半）**：`AmapClient._get` 自带退避重试
    （限流类 infocode + 网络错误才重试，指数退避带抖动，默认 3 次，上限 8s）。
    **别再手写固定 `sleep 1.5`** —— 那条是空闲时也白付成本的旧做法，自适应只在
    **被拒之后**才付。断言见 `tests/test_amap_backoff.py`。

- **坑：差点推荐一家「暂停营业」的店**（石岐佬东区店）。
  → **立规矩**：POI 的营业状态是可抓的，写推荐前必须核。
  → **怎么验的**：`search_places` 返回的名字直接带「(暂停营业)」，改用张溪店。

- **坑（最该记的一条）：过了闸门就改报错，忘了回写事实源**。
  为过 `evaluate` 调了 D2 全部时段并重渲染了 HTML，但事实源 `slots` 还是旧时间——
  同一决策点出现两个值；避雷里另有一条活条款写「稻田放 15:00 后」，而稻田早被并进 14:15 段。
  → **立规矩**：任何数字改动，**先改事实源 → 再改 itinerary → 最后渲染**，顺序颠倒必留残留。
  → **怎么验的**：从 HTML 里 regex 抽出全部 `HH:MM` 做计数交叉核对，确认新值全在、旧值归零。

- **坑（假绿）：把方案层文件喂给行程层检查，拿到一个看不出破绽的 `FEASIBLE 100`**。
  ③ 号闸门 `evaluate` 要的是**行程层** `itinerary_*.json`（有 `activities`），
  我却喂了**方案层** `final_plan_*.json`（只有 `days`/`segments`）。
  于是 `activities` 为空 → 所有规则被跳过 → 返回 `score 100`。
  那次是中山"四闸门全绿"里的一道，**它的绿是假的**（`summary.activity_count` 就是 0，我没看）。
  → **立规矩**：跑闸门别只看 status/score，**先看 `summary` 的计数**——
    计数为 0 的"全绿"等于什么都没查。
  → **已加固**：`feasibility.py` 新增 `EMPTY_ITINERARY`，
    `activities` 为空时明确指出"你可能喂的是方案层文件"，不再静默给 100。
  → **怎么验的**：喂 `final_plan` → `EMPTY_ITINERARY` 命中且不再给 100；
    喂 `itinerary` → 正常判定且 `activity_count=21`。
  → **2026-09-28 追加加固（提为阻断级）**：原先是 WARNING，实测结构错误的输入仍然
    得到 `FEASIBLE_WITH_RISK / 88 / **退出码 0**`——**从任何自动化的角度看都是「通过」**，
    唯一防线是人去读 summary 计数。现已提为 HARD：无内容可查一律 `INFEASIBLE` + 退出码 2。
    **机器断言**：`tests/test_evaluate_guards.py`（11 条，含 CLI 退出码契约）。
    → 教训：**「警告 + 退出码 0」不是防线，是提醒**。凡是「什么都没查」的结论，
      必须让程序能感知，否则接进 CI 的那个人拿到的是假的绿。

- **同源坑（更隐蔽）：`score 100` 只覆盖"被填上的字段"**。
  中山 21 条活动里只有 **3 条**填了开放时间窗、**2 条**填了来源时戳，
  所以 `BEFORE_OPENING` / `AFTER_CLOSING` / `STALE_SOURCE` 这几类**根本没机会触发**。
  100 分的准确含义是「在已填信息内没找到冲突」，**不是「方案优秀」**。
  → **已加固**：返回值新增 `coverage`（`activities_with_time_window` /
    `activities_with_source_time`），**不进分数**，只为让 100 分不再被误读。
  → **立规矩**：报"闸门全绿"时要连 `coverage` 一起说，别只报分数。

- **坑：`agent-browser` 在本机没装**（`command not found`），也没有 Chromium 缓存，
  所以第 20 项「真机截图亲验」这次**没做**。
  → **立规矩**：交付时如实列出没做的检查项，不假装验过。
  → **怎么验的**：`node -e` 可用、`agent-browser --version` 报 command not found、
  `%LOCALAPPDATA%\ms-playwright` 目录不存在。

### 2026-09-27 P1 · 修 `ludbook_check.py`（不是行程，是修闸门本身）

**背景**：审计发现 26 项自查在 HTML 交付路径上只跑了 C 组几项（实际覆盖率约 1/4），
「全绿」名不副实。补 A/B/D 组进 HTML 模式时踩的坑，全在**判据层面**。

- **坑：判据写宽了，一次跑出 55 处噪声。**
  ① 数字溯源最初写成「任何 `¥金额` 都要溯源」+「表格里程逐行判」，中山那份报出
  **55 处裸数字**——其中 14 行是表格里共享表外一处来源的里程，其余是预算汇总、
  复述行、伴手礼与茶位费单价。
  → **立规矩**：写检查器前先回读**该检查项的文档原文**，按语义边界划判据。铁律 1 说的是
  「票价」，指门票/车票一类**决策依赖**的价格；小吃单价、茶位费不属其列。判据过宽 = 噪声，
  **噪声大的闸门一定会被绕过**——那比不设闸门更糟。
  → **怎么验的**：改完后中山 55 → 0 处；另造一个「完全没写来源」的样本确认仍报错
  （降噪不能降成哑巴）。

- **坑：表格里的数字天然共享一处来源，逐行判必误报。**
  里程表 14 行全在表内，来源写在表外一行。
  → **立规矩**：先判「整表能否回溯到来源」——能则整表撤出逐行检查，**并把表内数值登记进
  「已溯源池」**，这样正文复述「11.7 公里」不会又被当成新的裸数字。
  → **怎么验的**：撤出后「共约 36 公里」这类**合计值仍被报出**（它确实是算的、不是查的）——
  这条保留报警是对的，说明豁免没过头。

- **坑：日程分块被切重，餐行检查拿导航块去查早/午/晚。**
  中山 HTML 里「第 1 天」在速览导航区、「D1」在正文区 → 切成 6 块，
  于是 Day1 被误报「早/午/晚全缺」。
  → **立规矩**：按编号归并，**同编号取文本最长的那块**（正文）。
  → **怎么验的**：分块 6 → 3，餐行缺失 3 天 → 0 天。

- **发现（比坑更重要）：第 2 项「证据分级标注」在工具链上没有落地路径。**
  `evidence-rules.md` 明确要求文中写 `[A]`/`[B]`/`[C·单源]`/`[D]`，但**事实源模板无此字段、
  `render_html.py` 不识别、基准骨架无样式**——成都基线与中山实战两份产出都只有「来源 + 时戳」
  而无标记；且铁律 1 的格式示例 `¥350（2026-09-27 13:00 查·长隆官方公众号）` **本身就没有 `[A]`**，
  规范内部口径也不一致。
  → **处置**：判据分两档——「既无标记也无来源时戳」才是阻断（拦真正没做证据工作的那份）；
  有来源时戳但缺标记给**提示级**，并写明这是工具链缺口。补齐工具链后方可升回阻断级。
  → **怎么验的**：`[A]` 在模板、渲染器、骨架、两份产出上 grep 计数**全部为 0**。

- **发现：成都示例是「渲染演示稿」，不是完整路书**——正文 2520 字符（中山 9031），
  Day1/Day2 各只有标题一行、所有分区堆在 Day3、无「拍」维度。
  新闸门对它报「⑮ 缺拍维度 / ⑯ 餐行不全」，**红灯是对的**：它本来就不是完整路书。
  → **立规矩**：`产出示例/路书_成都_渲染示例.html` 只用于**版式与渲染回归**，
  不适用内容层 26 项自查。旧闸门对它给「全绿」，正说明那个绿是残缺的。
  → **另**：改了检查逻辑后必须复跑渲染回归，确认**整文件仍与基线逐字节一致**（本次一致）。

### 2026-09-27 P2 · 收口 12306 MCP（不是行程，是修能力边界）

**背景**：P2 最后一项要「接入 12306 铁路 MCP」。结论是**不接**，并把虚假指引改掉——
过程比结论更值得记。

- **实测 1：MCP 市场里没有 12306 官方 server。**
  按关键词（12306 / 火车票 / 铁路 / 高铁 / 车次）搜可获取的连接器市场，返回的都是
  **第三方 OTA 与差旅聚合**——同程程心、途牛（OTA：机票+火车票+酒店+门票），
  合思、用友、分贝通、美团企业版（企业差旅，需企业账号）。
  → **立规矩**：第三方聚合查到的车次只能算 `[B]`，**不能当 `[A]`**（`[A]` 要求工具实证，
  且是「12306 官方或等效直连」）；企业差旅类对个人行程**不适用**，别把它当候选。

- **坑：`doctor` 让用户去运行一个本包根本没有的脚本。**
  `diagnostics.py` 检测 `data_dir/mcp-server-12306/` 运行时，MISSING 时给的建议是
  「Run `setup_rail_mcp.sh` from the installed Skill」——但 `setup_rail_mcp.sh`、
  `rail-mcp.md`、`patches/mcp-server-12306-security.patch` **在本仓库一个都不存在**
  （它们是上游的文件，融合时没搬）。照提示做必然卡住。
  → **立规矩**：报错文案里的**动作指令**（「运行 X」「参见 Y」）必须与包内实际文件一致；
  写指引前先 `ls` 一遍。**指引不在 import 链上，改文件名时没人会想起来同步它。**
  → **怎么验的**：`find . -name "setup_rail*"` 返回空；改完后重跑 `doctor`，
  `actions[0]` 已变为「Rail (12306) MCP 是可选且未随包分发……铁路事实保持 `[C]/[D]`」。

- **发现：`audit.py` 对这类问题报「✅ 未发现问题」。**
  它只扫**文档**里的路径引用，扫不到**代码字符串**里的文件名。
  → **处置**：在 `skill-doc-code-audit/SKILL.md` 的人工清单新增 **⑪ 代码里引用的本包文件是否真的存在**，
  并给出可复用的 grep 与误报提示（`hashlib.md5` 会被截成 `hashlib.md`；`__pycache__` 命中要先清缓存）。

- **处置原则：不能假装接入。** 与其塞一个来源不明的第三方 stdio MCP（它执行本地代码，
  且上游社区连接器明确声明不用于商业用途），不如把**能力边界写清楚**：
  铁路项默认走只读网页核验 `[C]` 或标 `[D]`，接入须自备并先做安全审查。
  这正是铁律 1 与「能力先测后报」的用法——**报「没有」比报假的「有」值钱**。

### 2026-09-27 · 补齐「证据标记」工具链（第 2 项从提示级升回阻断级）

**背景**：P1 时发现第 2 项「证据分级标注」**在工具链上没有落地路径**——`evidence-rules.md`
要求正文写 `[A]/[B]/[C·单源]/[D]`，但事实源模板无示范、`render_html.py` 不识别、骨架无样式，
两份产出 grep `[A]` 全为 0。于是它被降成提示级。这次补上了。

- **落地方式：行内标记 + 渲染期转徽章，不给事实源加字段。**
  规格本来就写着「标记写在正文里」（`4.2 公里，车程 18 分钟（…高德路线）[A]`），
  所以只需要一个渲染钩子 `hook_evidence_badges()`，把 `[A]`/`[B]`/`[C·单源]`/`[D]`
  转成 `<span class="ev ev-a">A</span>`。附加说明（`[C·单源·小红书2026-09帖]` 中点后半段）
  渲染成徽章后的灰色小字，信息不丢。

- **坑：钩子必须避让标签内部与 script 块。**
  直接把整份 HTML 丢给正则会误伤两处——`<span title="等级[A]">` 这种属性里的方括号，
  以及 JS 里的 `arr[B]` 这类下标。做法是先把 `script/style` 整块与其余标签 stash 成
  `\x00N\x00` 占位，替换完再放回。**负例测试比正例重要**：8 个用例里有两个专验「不该动的地方确实没动」。

- **坑（真踩到）：徽章数只能数「原始 HTML」。**
  `ludbook_check.py` 的 HTML 模式是先把标签剥成纯文本再送进 `check_content()`，
  `class="ev ev-a"` 一剥就没了 → 第 ② 项误判成「全篇零等级标」，而渲染明明出了 54 枚。
  修法是给 `check_content()` 多传一个 `raw_html`：**内容判据用纯文本，产物判据用原始 HTML**，
  两者别混。这和「⑩ 判据要与文档口径对齐」是同一类问题的另一面。

- **改骨架样式 = 改版式指纹。** `consistency.py` 的指纹是**基准骨架 CSS 的 MD5**，
  基准一变，既有产物全部「不一致」——这是刻意设计（指纹是活真值、不硬编码），
  但意味着改样式必须**重渲染全部示例并更新记录里的指纹文字**。
  本次 `9c3c6249a4` → `cd440ea068`，成都基线 MD5 `62d39f53…` → `49292d62…`。
  **同一规律也适用于改内容**：2026-09-28 示例去当事人信息（中性化）后，成都基线
  再次重建为 `f0cd1f68…`。**改骨架要重渲染，改事实源也要重渲染**——否则「逐字节
  复现」这条最硬的回归会当场报红（那正是它的用处：产物与源不一致时它先炸）。

- **标注是内容工作，不能批量刷。** 中山 54 处逐条判：`[A]` 只给高德工具返回（路线/评分/营业状态）
  与政府门户（詹园票价）；`[B]` 只给两个独立来源一致（同程+携程的城际票价、携程+马蜂窝的影视城票价）；
  单 OTA 与单一攻略一律 `[C·单源]`；查不到的标 `[D]` 并给确认方式。
  v1 终值 **A22/B10/C16/D6**（54 枚）；v2 并入社媒情报后 **A26/B20/C25/D15（86 枚）**。
  **宁可标低不标高**——`[A]` 标多了，铁律 1 就成了装饰。

- **标注脚本要带「命中即校验」。** 锚点用 `str.replace(old, new, 1)` 批量插入，
  每处先断言 `count(old) == 1`，不满足就整脚本退出、不写盘。实际抓到 1 处锚点写反顺序
  （我自己记错了 `（携程…）` 与 `<b>整栋楼…</b>` 的先后）——**批量改文本必须有这道闸**，
  否则是静默漏改。
  > 另：这处总数字曾写作「45 处」，与同段的分项表 `22+10+16+6` **自相矛盾**。
  > 实测事实源 `[X]` 标记为 54 处。**分项表加总就是最便宜的交叉验证**——写总数时顺手加一遍。

## 写事实源前先看：引擎与数据的 12 个坑（2026-09-27 首次实战确认）

> 这一节是从项目长期记忆里搬过来的——**这些坑不看文档就会重踩**，
> 而它们原本只存在于记忆文件里。凡「写事实源前该知道的」，都收在这里。

1. **`validate-plan` 的 `features` / `why_visit` / `source_refs` 必须是数组**——
   引擎的 `_strings()` 只吃 list，写成字符串会被判空，报 `has no reason to visit`。
   **报错信息完全不提示这个原因**，第一次遇到会以为是内容缺失。
2. **`evaluate` 单日跨度硬上限 720 分钟（12 小时）**，超了报 `DAILY_DURATION_EXCEEDED`。
   注意它是 `span > 720` 才警告、`available < required` 才阻断 —— **卡线是安全的**。
3. **事实源 JSON 正文里的中文引号必须用「」**，写英文 `"` 会让渲染器
   `FATAL 事实源不是合法 JSON`。
4. **高德 `CUQPS_HAS_EXCEEDED_THE_LIMIT (10021)` = 并发/QPS 限流，不是日配额**——
   现在 `AmapClient._get` **已内置**退避重试（限流类 infocode 与网络错误才重试，
   指数退避带抖动，默认 3 次 / 上限 8s；`10003` 日配额与 2xxxx 参数错**不重试**，
   等下去改变不了答案）。**不用再手搓 sleep**。规矩的机器断言在 `tests/test_amap_backoff.py`。
5. **`segment.buffer_minutes` 优先于 activity 的 `required_buffer_minutes`**——
   想用后者生效，必须先把前者从该段删掉。
6. **改数字的正确顺序：事实源 → itinerary → 渲染。** 颠倒必留残留
   （实际踩到：改了 itinerary 忘了回写 slots，同一决策点出现两个值 + 避雷里的活条款没归零）。
7. **`evaluate` 只认行程层 `itinerary_*.json`；喂方案层 `final_plan_*.json` 会得到假绿。**
   `activities` 为空 → 所有规则跳过 → 干净的 `FEASIBLE 100`。
   **2026-09-28 起 `EMPTY_ITINERARY` 已提为阻断级**（severity HARD → `INFEASIBLE` + 退出码 2），
   不再需要靠人读计数兜底；断言见 `tests/test_evaluate_guards.py`。
   即便如此，**跑闸门仍先看 `summary` 的计数**：计数为 0 的「全绿」等于什么都没查。
   另：`coverage` 字段不进分数，它告诉你闸门**实际查得到多少**——
   **`score 100` 只覆盖被填上的字段，不等于方案优秀。**
8. **重建结构化数据后先比 `coverage`**：v2 重建 itinerary 时漏带 `opening_time`/`closing_time`/
   `last_entry_time`/`source_checked_at` → `evaluate` 照样 `FEASIBLE 100` **零警告**，
   但 `coverage` 从 3/2 掉成 0/0。**闸门变哑 ≠ 行程变好**。
   修法 = 按 `KEEP` 列表从旧活动继承。
9. **三个 JSON 的行尾不统一**：事实源是 `indent=2 + CRLF`，`itinerary`/`final_plan` 是**纯 LF**。
   无损往返校验必须**按文件自身嗅探行尾**（Python 里写 `b'\r\n' in raw`）；
   写死 CRLF 会把后两个误判成「格式不符」并中止写盘——**是校验的问题，不是文件的问题**。
10. **中文关键词闸门必须过一遍分词边界**：「本次没排**进**行程」被裸正则判成 AI 味词「进行」。
    已加 `AI_WORD_EXCEPTIONS` 例外表。
    **遇假阳性改闸门，不改本来正确的好文案**——改文案等于把闸门调松。
11. **`final_plan` 的 `start`/`end` 应从 `itinerary` 回填**（生成脚本已做）：v2 曾漏删
    `d2_dinner`（旧「回城晚餐」），带着旧时刻留在方案层——「改了行程没回写」的典型残留。
12. **「grep 关键词」判风控会误报，同一模式已栽两次**——B站搜索页把页头的
    「**登录**」按钮文案当成了登录墙（实际 DOM 1.1 MB、42 张卡片完全可读）；
    复测详情页时又把 CSS 里的 `background-position:-3520px` 当成了风控码 `-352`。
    **判风控必须看返回体特征**（状态页标题 / 错误 JSON / WAF 脚本），不是关键词。
    同源问题：`ludbook_check` 的 AI 味词表也是裸正则（「本次没排**进**行程」被判成「进行」），
    靠例外表兜。**凡关键词类判据，交付前都要跑一次假阳性样本**——否则闸门会教人改坏文案。
