# 证据分级细则

本文件是 `SKILL.md` 铁律 1 与「证据分级」章节的展开。只在需要判断某条信息该归哪一级时读它。

---

## 为什么必须分级

AI 做攻略的最大隐患不是"写错"，是**把不同可信度的东西混在一起写**。于是读者分不清：

- 「高德返回的车程 18 分钟」（机器实测）
- 「某篇攻略说这边很好逛」（个人体感）
- 「听说门票大概 300 多」（道听途说）

三者字面看起来一样，可信度差三个数量级。**分级就是把这三种东西在视觉上分开**，让读者一眼知道哪些能直接依赖、哪些要自己再确认。

---

## 怎么落到路书里

等级标**直接写在正文里、紧跟那个数字**，例如：

```
4.2 公里，车程 18 分钟（2026-09-27 查·高德路线）[A]
本地菜馆（人均 60）[B]（点评 4.6 + 地图在营，2026-09-27 核）
14:00-16:00 常有雷阵雨[C·单源·小红书2026-09帖]
门票价未核实[D]——请到官方公众号搜「XX景区门票」确认
```

渲染时 `render_html.py` 会把它转成小徽章（`.ev`）：四档配色不同（越实越绿、越虚越红），
鼠标悬停显示等级全称。**所以事实源不需要为此加字段——标在句子里就行。**

`[C·单源·小红书2026-09帖]` 这种带附加说明的写法，中点后面的内容会渲染成徽章后面的灰色小字。

## 四级定义与判定

### A 级 · 工具实证 `[A]`

**定义**：数字直接来自工具调用或官方渠道的返回值，未经模型加工。

**可用来源**：
- 地图服务返回的 POI、坐标、路线时长与距离
- 铁路查询返回的车次、时刻、余票、票价
- 景区官网 / 官方公众号 / 官方 App 的门票价与开放时间
- OTA 在售页的可见价格（须带渠道名 + 登录态）

**硬性要求**：
- 必须带**来源名**与**查询时戳**
- 格式：`¥350（2026-09-27 13:00 查·长隆官方公众号）`
- 路线类：`4.2 公里，车程 18 分钟（2026-09-27 13:00 查·高德路线）[A]`

**时效阈值**（超过须重查，重查失败降级为参考价）：
| 类型 | 有效期 |
|---|---|
| 机票价格 | 2 小时 |
| 火车票余票 | 24 小时 |
| 酒店房价 | 12 小时 |
| 门票价格 | 当天 |
| 营业时间 | 30 天 |
| 换乘路线 | 出行当日 |

---

### B 级 · 多源交叉 `[B]`

**定义**：≥2 个相互独立的公开来源信息一致。

**判定组合**（满足任一即可升 B）：
- 点评高分店铺 + 地图 POI 显示在营 + UGC 多帖提及
- 官方公众号公告 + OTA 在售页价格一致
- 两个不同平台的榜单同时收录

**写法**：`[B]` + 至少两个来源名 + 核实日期
例：`本地菜馆（人均 60）[B]（点评 4.6 + 地图在营，2026-09-27 核）`

**不可升 B 的情况**：
- 两个来源其实是同一篇内容的转载
- 一个来源本身就是另一个的聚合（如某 App 抓的点评数据）
- 只有标题/简介一致，正文没说

---

### C 级 · 单源线索 `[C]`

**定义**：只有 1 个来源，或来源本身是 UGC。

**允许的用途**（只能用于这几类）：
- 路线顺序建议（"先到这里再到那里比较顺"）
- 人流/排队体感（"周末下午人很多"）
- 季节时机（"11 月中下旬最好"）
- 体验描述（"栈道缝里能看到云海"）

**硬性禁止**：C 级信息**绝不能**用于——
- 门票价格
- 营业时间 / 开放状态
- 车次 / 航班时刻
- 余票
- 距离 / 车程

> 这条是死线。UGC 里写的"门票 80"、"9 点开门"、"从高铁站打车 20 分钟"，
> **全部不可采信**——那些必须回官方渠道、地图或 12306 重新查一遍。

**写法**：`[C·单源]` + 来源类型 + 日期
例：`14:00-16:00 常有雷阵雨[C·单源·小红书2026-09帖]`

---

### D 级 · 未核实 `[D]`

**定义**：查不到 / 来源失效 / 多源矛盾无法调和。

**必须做的事**：
1. 在文中**如实写明**「未核实」
2. 给出**用户可自行确认的方式**（哪个 App、搜什么词、打什么电话）
3. 汇总进交付时的「未核实项清单」

**写法**：`门票价未核实[D]——请到官方公众号搜「XX景区门票」确认`

> 禁止的行为：用"大约""通常""一般在"把 D 级信息糊过去。
> 那等于把未核实伪装成 A 级，是本 skill 最不能接受的行为。

## 多源矛盾的处理

**原则：并列写出，不擅自裁决。**

正确：
```
开放时间存在两种说法：
- 09:00-17:00（景区官网，2026-09-27 查）[A]
- 08:30-18:00（某攻略帖，2026-08）[C·单源]
建议以官网为准，出发前电话确认：0755-XXXXXXX
```

错误：
```
开放时间 09:00-17:00
```
（擅自选了一个，读者不知道还有另一种说法）

**例外**：当一个是官方源、另一个是 UGC 时，可以给出倾向性建议，但**两个说法都要写出来**。

## 境外目的地的特殊处理

多数国内地图服务**对境外查询不返回空，而是返回同名国内地点**：

| 查询 | 实际返回 | 危险 |
|---|---|---|
| 东京 | 广西某村庄 | 坐标格式完全正常，像真的一样 |
| 捷里别尔卡 | 贵州某地 | 会污染所有基于它的距离计算 |

**必须做的**：
1. 用**已知在国内**的测试点验证覆盖范围
2. 识别出这类"同名替换"并**拒绝使用**
3. 进入境外模式后：
   - 不得声称验证过 POI / 坐标 / 地面路线
   - 不得用地图数据生成换乘段
   - 车次不可用（12306 只覆盖大陆）
   - 网页调研成为唯一来源，路书必须**明确说明**这一点
   - 可行性检查仍跑，但要说清「哪些检查因无路线数据而跳过」

## 自查口诀

交付前对每条数字问三个问题：

1. **它从哪来？**——说得出来源名吗？
2. **它什么时候查的？**——有时戳吗？过有效期了吗？
3. **它配得上 A 级吗？**——如果来源是 UGC，凭什么印在票价栏里？

三个都答得上，才允许它以 A 级出现。

## 机器核验（标注纪律的闸门）

上面的口诀原本靠人念——**`tools/source_audit.py` 把它变成可判定的规则**：

```bash
python tools/source_audit.py --facts 路书_XX_事实源.json --plan final_plan_XX.json
```

源核验 8 条规则（E1-E8）逐条核对本文档的四级定义与死线：`[A]` 有没有时戳与来源、
`[B]` 数不数得出第二源、门票价/车程/时刻有没有落在 `[C]`（死线）、`[D]` 有没有给出路。
有 FAIL 退出码 2，与 `evaluate` 同一纪律：**排不通不交付**。

> **标注是声明，核验才是证据。** 写到路书里的每个 `[A]` 都要过这一关——
> 一个人念口诀会漏，机器不会。判定细节（归属模型 / 语境收窄 / 示例定位）见
> `references/source-audit.md`。
